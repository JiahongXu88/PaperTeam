## 1. M13.7.8 的 B 为什么词面重复率失败却保住了全部科研事实

M13.7.8 用的是 M13.7.7 的词面探测器（CJK bigram + 拉丁 token，containment ≥ 0.5 且 Jaccard ≥ 0.2 即记"后节 ≈ 前节"），它只回答"哪两句词面相近"，不回答"哪一句没有学术价值"。对 M13.7.8 四臂 48 个 pair 的逐句分类（本轮用确定性规则重做，结果与当时的人工分类一致，见 §3）表明：

- Baseline（A）的 13 个复述句里，**10 个确实有害**：引言把四种机制先讲完一遍（P ×5，约 276 字）、两个 develop 节各写一次"本节论述依据摘要、未涉及本文实验"（L ×2）、结论逐一复述 BYOL / SimSiam 机制（M ×2）、比较节把 SimCLR 的批规模句原样搬过来（X 逐字 ×1）。
- B 的 11 个复述句里只有 **6 个有害**，而且性质全变了：4 句是任务块诱导出来的路标句（"将在「无负样本的孪生方法」一节展开"等，约 183 字）、2 句是比较节对 SimSiam 句子的逐字搬运（containment 0.885 / 0.824）。P、L、M 全部归零。
- 探测器把 B 的路标句计为复述（路标句之间互相"相似"：都含章节名与"展开 / 见…一节"），又把比较节的逐字搬运计为复述，所以词面占比 27.8% 反而高于 A 的 23.9%；但 B 的 Evidence 按节分配、长度是上限而非配额、任务块逐项点名要转述的结果，这三点使它成为四臂中唯一全保 76.5% / 7% / 85.8% / 1% / 7 项 / 74.3% / 79.6% 的稿件。

所以 M13.7.8 的"失败"是指标与方案的错位：方案消灭了 Baseline 的三类有害重复，制造了一类新的（路标模板）并保留了一类（比较节逐字），探测器一视同仁。本轮不把 M13.7.8 改判——它的预注册指标是词面占比，结论 FAIL 不变；用本轮的新指标回看，B 的有害占比 14.7% 对 A 的 18.5%（−20.5%），**同样达不到 −30% 的门槛**。

## 2. 有害学术重复评价框架

### 2.1 设计

新模块 `backend/src/review/academicRedundancyClassifier.ts`（纯函数，+10 项单测），只消费探测器的候选 pair，不删除、不替代既有功能，不接入 Reviewer / Gate / Revision。对每个 pair 给一个类别、命中的规则编号与可解释理由，并把"有害"归到正确的一侧（引言预展开时有害的是引言句，不是 owner 句）：

| 类别 | 判据（规则） | 有害侧 |
| --- | --- | --- |
| **L** 限制 / 免责重复 | R2：两侧都是限制句（探测器哨兵）。compare 允许；framing / conclude 允许第一句；develop 不允许。develop 一侧只有在与另一 develop 节重复、或本节 ≥ 2 条限制句时才确定有害，单独一句且对方在 compare / framing / conclude 记 uncertain（R2u，可能是 owner 节对 partial 证据的合法界定） | 不被允许的一侧 |
| **S** 模板化路标 | R1：任一侧是路标 / 交叉引用句（"见「X」一节""将在「Y」一节展开""如前所述"等 10 组正则；路标片段占句 ≥ 50%、剩余 < 24 字或以交叉引用谓语收尾）。引言的路线图句是惯例不计有害；其余位置有害；未进入任何 pair 的孤立路标句同样计入 | 路标句一侧 |
| **F** 误报 | R3：较短一侧 ≤ 30 个信息单位（CJK 字 + 拉丁 token）且 Jaccard < 0.3——短标签 / 枚举句被长句包含 | 无 |
| **X** 必要对照提醒 | R5：develop 节首的承接句（自带对照标记，或与前一 develop 节的收束 / 对照句相接）；R7：compare 节的提醒。containment ≥ 0.8 记逐字搬运（有害）；∈ [0.7, 0.8) 且 Jaccard ≥ 0.4 记 uncertain | 逐字时后节句 |
| **P** 引言预展开 | R4：develop 后节 ≈ framing 前节，且 framing 句 ≥ 36 个信息单位；更短记 uncertain（路线级描述与机制难辨） | 引言句 |
| **M** 机制 / 结果完整重述 | R6：develop 对另一 develop；R8m：结论中 ≥ 2 句各自与机制陈述句（develop 的非收束句，或已判为 P 的引言句）配对——"逐一复述" | 后节句 |
| **E** 必要概括 | R8：结论对框架 / 主要结论的呼应。containment ≥ 0.8 记逐字（有害）；对 compare 综合句与"总体而言…"收束句的呼应永远是 E，不升级为 M | 逐字时结论句 |
| **uncertain** | R2u / R4u / R7u / R9（非常规顺序） | 不计下界，计上界 |

两个指标并列输出：**指标 A** = 探测器原封不动的词面复述占比；**指标 B** = 有害句字符 / 全部句字符，给出下界（不含 uncertain）与上界（含）。报告同时给原始 pair 数、分类后各类 pair 数、有害句数与字符、正文句字符、逐句原文与理由（评估 JSON `classification.pairs / harmfulSentences / uncertainSentences / signpostSentences`）。

同轮对探测器 `crossSectionRedundancy.ts` 的限制句哨兵做了冻结前补充（"不涉及本文自己的实验""不作横向排序""作者自述""仅为四篇摘要"），只影响限制统计与 L 判定，不影响 pair 与指标 A；`\%` 修复行为由既有单测守住，并在分类层新增一项"`\%` 之后句子仍被分析"的测试。

### 2.3 它是否减少误判而不纵容真正的机制重复

- 不纵容：A 的 10 个有害句一个不漏；比较节逐字搬运（7.8 A/B/C/D 各 1–2 句）全部命中；结论逐一复述（7.8 A、7.7 A）命中。X / E 不因"在比较节 / 结论"豁免——containment ≥ 0.8 照记有害。
- 减少误判：短标签句被长句包含（"二是无负样本的孪生方法，以 BYOL 与 SimSiam 为代表"）记 F；比较节带对照结论的提醒记 X 不计有害；引言范围声明、compare（局限性 owner）与结论一句承接的限制重复不计有害；develop 节孤立限制句（可能是来源本身的科学限制）记 uncertain 而非有害；节首 / 节间过渡句记必要过渡。必要引用、重要数值从不因出现而被判删除。
- 已知盲区（held-out 阶段确认，未改规则）：① 限制哨兵漏掉"不能**据此**给出…排序"这类副词插入的写法，使对齐主题 B2 结论里协议要求的一句限制承接被判成 E 逐字（1.6% 全部来自它；人工判不有害）；② 词面探测器对改写过的引言预展开召回不足（对齐 A 的宪法式 AI 预展开、量子纠错 A 的 Sivak / Ni 预展开都没配上对，所以 A 的指标 B 其实偏低）；③ 概念标记看不见 `$…$` 数学模式里的数字（探测器把数学整体替换为占位符），量子纠错主题 12 项数值全部靠人工核对。这些都是评价器下一轮要修的点，不影响本轮方向性结论（盲区①使 B2 偏高、盲区②使 A 偏低，都对 B2 不利）。

## 3. B → B2 精确改了什么

只改实验输入组织中的任务块（`argumentUnitsV2`），Evidence 分配、长度上限（180 / 400 / 400 / 320 / 160）、`lengthPolicy`、长度措辞替换、生产 `buildSectionPrompt` 全部沿用 M13.7.8 Arm B；干跑 diff 确认 B 与 B2 的 prompt 只在 `===== 本节论证任务 =====` 块内不同，新 runner 重建的 M13.7.8 A / B prompt 与当时 LIVE 的 prompt 逐字节相同（5/5 + 5/5）。差异（`dev-simclr.json#argumentUnitsV2.changes`）：

1. `doNotExplain` 每项不再渲染"（见「X」一节）"——只列概念，owner 节 id 留在数据里用于校验；
2. 一条行为约束 `crossSectionPolicy` 取代逐项路标："跨章节分工只约束本节写什么、不写什么，分工本身不进入正文：不写「见某节」「将在某节展开」「已在前文说明」…不在节首或节尾预告、回顾论文结构；需要承接时直接点出对象或差异，用半句自然过渡即可"；
3. 各节 `task` 删掉所有"说明它们分别在「…」两节完整展开""最多一句回指「…」一节""机制细节回指前两节"；
4. compare 角色重写为 Synthesis / Comparison：依次回答关键差异（给定维度，每个维度落到一个对照结论，机制只以半句提醒出现，不复制前两节的句子）、现有证据能支持哪些结论、哪些结果不可直接横向比较、目前证据还不能判断什么（partial 负对照点名），仍是全文唯一集中陈述限制的位置；
5. conclude 任务追加"不写指向其他章节的句子"，保留一句限制承接。

没有新增长篇 Prompt，没有概念所有权协议；任务块长度与 B 相当（比较节 prompt 17.6k vs 17.3k 字符）。

人工逐 pair 核对（私人 `heldout/manual-reading-heldout.md`）：四臂 50 个 pair，规则判有害的 12 句中 11 句与阅读一致，唯一分歧是上述盲区①；阅读没有发现规则漏判的有害句（配对内），但发现两处探测器没配上对的引言预展开（对齐 A 的宪法式 AI、纠错 A 的 Sivak / Ni），说明 A 的指标 B 是低估。

## 9. 是否值得进入生产集成

值得。预注册的六项验收顺序：① 必保事实与数值全部在位（两主题）；② 没有新增 Evidence 未覆盖的机制或强结论（B2 ≤ A，A 反而有一处红旗）；③ 引用全部合法且语义相关（未知 key 0，cite 分布与 owner 一致）；④ 有害重复显著下降（−88.8% / −100%，两个 Baseline 都高于区分度下限）；⑤ 路标模板与逐字比较回述归零，没有成为新缺陷；⑥ 费用 −18.5% / −22.9%、时间 −46% / −42%。按协议判 **PASS — Ready for Production Integration**。

PASS 的边界：单次采样（GLM 输出不确定，"−88.8%"的具体数字不可外推，但两个主题 + 开发集三次方向一致）；角色 / evidenceIds / doNotExplain 由人写夹具提供，真实 Planner 能否稳定产出未验证（M13.7.4 的 Planner 失败是前车之鉴）；B2 没有遵守 develop / compare 的长度上限（对齐 538 / 414 / 465 对 400 / 400 / 320，纠错 499 / 464 / 488），"宁可写短"只在引言与结论生效——事实没有因此丢失，但说明上限语义不能当作长度控制手段；评价器三处盲区（§2.3）；本轮没有跑 Review / Revision / Gate / 全文 E2E。

## 10. 生产集成最小改动点与风险（只给方案，本轮不改）

1. `writingSectionsStage`（`backend/src/workflow/definitions.ts` 的证据选择在循环之前只算一次）：改为逐节选择——Outline 可选字段 `evidenceIds` 优先，缺省时按节 keyPoints 调 `EvidenceSelectionService.selectForWriting`；framing / conclude 角色传空集并只给 B 组背景 key；partial 记录只交给 owner 节与 compare 节。
2. Outline Schema 可选字段：`role`（framing / develop / compare / conclude 四值）、`task`（一段）、`doNotExplain`（概念字符串数组，由 owner 自动派生，不要求 Planner 写指向句）、`targetLengthUpperBound`。`buildSectionPrompt` 的"目标长度"行区分"约"与"不超过"，并把 `lengthPolicy` 与 `crossSectionPolicy` 作为两条固定句子加入（不是模板句，是行为约束）。
3. compare 角色的任务模板按 §3 第 4 条生成（差异 / 维度 / 证据能支持什么 / 不可比什么 / 不能判断什么），conclude 角色固定"一句承接限制、不写结构性回指"。
4. Planner 侧：由 Planner 生成 role / evidenceIds / task；`validateSurveyOutline` 增加确定性 warning：唯一 quote 字符 ≪ 要求总长时自动把 develop 节长度收到预算内；roles 不合法时回退到位置推断（`inferSectionRoles`）。
5. Reviewer / Gate：把分类器的有害句（M / L / P / S / 逐字 X / E）作为 style 提示注入 Reviewer digest（只报告、不改分数、不阻断），为后续 C 方案（owner 感知的定向压缩）留接口。

风险：Planner 生成 role / 证据分配的可靠性；长度上限不被遵守时对 Token 预算的影响（本轮 B2 仍比 A 短 10–33%，但不是靠上限）；评价器盲区①会在真实 Review 里把合法的结论限制承接误报，接入 Reviewer 前先修哨兵；数学模式数字在标记与分类层不可见，Fact Preservation 的数值守卫不受影响但评估报表要补；跨 Checkpoint 恢复时 `evidenceIds` 的持久化；Survey 路径（`buildSurveySectionContext` 按 refs 投影）与 idea_to_paper 路径要共用同一套角色 / 任务渲染。

## 11. 仍需独立解决的事实风险

- **机制句级 quote 覆盖核对**（M13.7.7 §8 已提出）：四臂都有引文没有的轻度推断，Baseline 在量子纠错主题上写出了摘要中不存在的编码名称并把"强化学习"扩成"强化学习解码"。这类错误与重复无关，输入组织不解决它；需要句级 claim decomposition + quote 覆盖判定，并把"合理阐释"从 Fact Reviewer 的放行理由中移除。
- **联合 cite 的归因稀释**：B2 的"微波腔光子数态等离散变量…\cite{ni, sivak}"用一个"等"字让只属于 Ni 的描述覆盖 Sivak；Citation Relevance 层应检查多 key cite 中每个 key 与句子的对应关系。
- **评价器三处盲区**（§2.3）在接入任何生产 Reviewer 之前先修，并按本轮纪律保留冻结数字作对照。
