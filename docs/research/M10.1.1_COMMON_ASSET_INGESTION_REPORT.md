## 1. 支持的文件类型与处理策略

| 类型 | 扩展名 | parser | 块形态 | provenance |
| --- | --- | --- | --- | --- |
| TXT | .txt | TextAssetParser("text") | text 段落块（空行分段） | lineStart/lineEnd |
| Markdown | .md | TextAssetParser("markdown") | text 块 + ATX 标题 → section_header/section（零新依赖，无 MD AST） | lineStart/lineEnd + section |
| LaTeX | .tex | TextAssetParser("latex") | text 块；`\section{…}` 等命令行 → section；源文本原样保留（不执行、不展开宏、无 TeX AST） | lineStart/lineEnd + section |
| JSON | .json | JsonParser | 每个标量叶子一条 structured_record（`$.training.epochs`；空容器 `[]`/`{}` 标记） | jsonPath（JSON.parse 无位置——行号缺省不伪造） |
| YAML | .yaml/.yml | YamlParser（`yaml` npm 包 AST + LineCounter） | 与 JSON 同型投影 | jsonPath + row（1-based 文件行） |
| 源码 | .py/.cpp/.cc/.c/.h/.hpp/.ts/.tsx/.js/.jsx/.mjs/.cjs/.rs/.go/.java/.sh/.ps1… | TextAssetParser("code") | code 行窗口块（≤50 行，优先空行边界；**单行永不截断**；无 AST） | lineStart/lineEnd + language |
| Notebook | .ipynb | NotebookParser（纯静态 JSON 解析） | markdown cell → text 块；code cell → code 块（language 自 kernelspec/language_info）；文本输出（stream/execute_result/display_data text/plain/error traceback）→ output 块；图片输出 → figure 块 + 解码落盘资产 | cellIndex（0-based=nbformat 下标）+ cellId + outputIndex + cell 内行号 |
| 图片 | .png/.jpg/.jpeg | ImageAssetParser（magic bytes + 头部尺寸读取） | 单 figure 块（登记：签名 + width/height + 资产复制到 figures 目录）。**无 Vision / 无 OCR / 无描述** | fileName + assetName + width/height |
| PDF/CSV/XLSX | 既有 | 既有四 parser（回归零改动） | 既有 | 既有 |

统一入口不变：`POST /sources` 上传（非 PDF 内联解析进响应汇总；PDF 后台
docling）、`POST /sources/:id/ingest`、`GET /sources/:id/document`。分派
唯一判定点：`backend/src/ingestion/parserRegistry.ts`（查表函数，非插件
框架；新增格式 = 扩表 + 实现 DocumentParser，业务层不改）。

## 2. 关键决策

- **为什么没有 AST**：本轮 RAG 的核心问题是「这个配置在哪里 / 这个脚本设了
  多少 epoch」——行级 provenance（train.py:5）已能回答；AST 需要全语言
  体系（tree-sitter/LSP）与符号库，属下一量级工程，且与检索收益不成比例。
  代码块策略 = 行窗口 + 语言标签，缩进与行完整性逐字保留。
- **为什么 Notebook 不执行**：ingestion 阶段执行任意用户代码是安全红线。
  NotebookParser 只做 JSON 读取 + base64 解码（纯字节操作，无执行语义）；
  execution_count 只是静态记录，不代表系统执行过。图片输出超上限（8MB/张、
  50 张/notebook）不解码不落盘，登记 `visualOutputPresent=true`——事实不丢，
  M10.2 可回捞。HTML/JS 输出只提取 text/plain，否则登记 mime 类型标记。
- **JSON/YAML 投影不是新事实源**：原始文件永远是 source of truth；投影只是
  可检索 / 可确认的视图。用户确认投影值沿 M10.1 通道：
  `POST /records/evidence` 新增 `path` 寻址（`$.training.epochs`），机械值
  校验同口径，`user_confirmed ≠ grounded_verified` 边界零变化（单测锁定）。
- **YAML 行号**：`yaml` 库（纯 JS、零传递依赖）AST + LineCounter 低成本
  提供 1-based 行号 → provenance.row；JSON 无行号（JSON.parse 不带位置，
  不自写 parser）——如实缺省，报告与代码注释均明确。

  parser 提供时才有，合并块取首尾范围）。

## 8. 当前限制（如实）

1. DOCX 不支持（明确边界，上传白名单拒绝）。
2. JSON 无行号（JSON.parse 无位置；不自写 parser）；YAML 复杂键（`?` 语法）
   按源文本键名投影；YAML 多文档文件按解析失败处理。
3. Markdown 标题只认 ATX（`#`），无 setext/HTML 语义；LaTeX section 识别不
   区分注释行内命令（源文本原样保留的代价）。
4. 源码无 AST / 符号；超长行不截断（行完整性优先），极端 minified 文件会
   产生超大单行 chunk 文本。
5. Notebook 输出确认通道未做（text/code/output 可检索可回溯；把「确认
   notebook 输出值」并入 records 通道属后续增强）。
6. 图片宽高读取失败时（损坏头部）仍登记但无尺寸（partial + note）。
7. 上传即自动解析对所有非 PDF 类型内联执行——超大文本（>2M 字符截断）与
   超大 notebook（块数/图片上限）有防御但上传延迟随文件增大。

## 9. M10.2 的直接接口

Vision 阶段可直接复用（零迁移成本）：

- `ParsedFigureBlock`：`assetName`（figures 目录内文件名）+ `width/height` +
  `visualOutputPresent`（回捞标记）+ provenance（PDF：page/bbox；Notebook：
  cellIndex/outputIndex；图片：fileName）。
- `GET /sources/:id/document?blocks=true`：块级枚举入口（M10.2 遍历
  figure 块 → 逐图 Vision 分析 → Candidate Facts → 用户确认）。
- `sources/figures/<sourceId>/` 目录：图片资产唯一落位（docling 抽图 /
  notebook 解码 / 上传登记同目录），随条目删除清理。
- Evidence 纪律不变：Vision 产物是 Candidate，进 EvidenceStore 仍须用户
  确认（user_confirmed）或三段核验（grounded_verified）。
