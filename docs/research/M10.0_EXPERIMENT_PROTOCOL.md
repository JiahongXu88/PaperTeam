## 1. 实验矩阵与阶段门

| 阶段 | 内容 | 通过标准（不过则停） |
| --- | --- | --- |
| **P0 冒烟** | §2 全部前置检查 | 模型平价链路通、三臂驱动器各产 1 份合规产物、采集器拿到完整 run-record |
| **Pilot** | 3 任务 × 3 臂 × 1 rep | ≥2/3 任务三臂全 completed；指标采集零缺口（除登记项）；主终点无天花板/地板（METRICS §7-5） |
| **Main** | 6-8 任务 × 3 臂 × 2 rep，随机化臂序 | DNF 率 ≤20%/臂；配对完整率 ≥75% |

每阶段出口写报告（`evaluation/reports/m10/` + `docs/research/` 解读），**pilot 报告
登记预注册调整后方可跑 main**（只许降级终点/修协议 bug，不许换方向性预期）。

## 3. 三臂驱动规程

### 3.0 公共规程

- 执行单位 = 一个 `run` = (taskCard, arm, rep)。**全局串行**（M9.8 教训：并行互抢
  限流；multiModel 先例：臂间停 4s、模型间停 4s）。
- 每任务内臂序随机（骰子记录进 manifest），rep 间间隔 ≥60s。
- 全程不人工纠偏：任何提示词修正=实验污染，该 run 作废重跑。
- 环境快照随行：git HEAD、网关 request id 列表、`/api/runtime/status` 快照（对冲
  审计 G3：模型身份以快照为准入 manifest）。
- 失败处理：基础设施错误（网络 5xx/超时/进程崩溃）→ 修因后重试 1 次；模型拒绝/
  质量差 → 如实记录为该 run 结果（refusal/DNF 也是数据，M6.9.2 先例：「拒绝编造」
  是合法测量结果）。

### 3.1 Arm P（PaperTeam）

1. `POST /api/projects`（researchIdea=topicBrief、language、documentType、targetProfile
   按任务卡）→ `POST /api/projects/:id/workflows {kind:"idea_to_paper"}`。
2. 轮询 `GET /api/runs/:runId`，HITL 断点按脚本决策 resume（`POST .../resume`）：
   `hitl.feasibility_confirm`→approve；`hitl.outline_confirm`→approve；
   `hitl.evidence_supply`→continue；`hitl.revision_validation`→**采用系统建议**
   （blocked 时 reject 恢复快照，即默认安全策略）；`hitl.revision_stalled/overflow`
   →accept_draft（终态记 draft，如实标注）。每次 resume 记入 interventions。
3. 成本采集器随 run 在线（轮询差分 + stdout 日志双通道，METRICS §5）。
4. 终态后离线收割全量遥测（AUDIT §3.7 路径清单）。
5. 超时：wallClockMin 到点 `POST .../cancel`，取最后完整 revision 快照产物。

### 3.2 Arm C（Claude Code）

1. 独立工作目录（每 run 一目录，空目录起步）；`claude -p "<任务卡全文>"
   --output-format stream-json --verbose --max-turns <N> --permission-mode acceptEdits`
   （N 与权限模式全实验冻结；工具集=默认含 WebSearch/WebFetch，不装 MCP）。
2. 会话规则：模型停下询问 → 追加一次中性 `continue`（计入 interventions，上限 3 次，
  超上限视为完成尽力而为）。
3. 产物要求随任务卡下发（LaTeX 模板路径、结构清单、引用下限）；结束时若产物不齐，
  追加一次中性 `deliver the artifacts as specified`（计入 interventions）。
4. 转录 JSONL 全量存档（F1 成本 + 过程审计的事实源）。
5. 超时：SIGTERM 后取目录内最后完整 .tex/.bib。

### 3.3 Arm L（chat-llm）

1. 直连网关 API（anthropic-messages 协议），system prompt = 任务卡全文 + 中性
   「你可以分多轮完成，自行规划」。
2. 轮次预算 = 固定 K 轮（P0-5 定标，建议 8-12）；除首轮外用户输入只有
   `continue`（计入 interventions）。
3. usage 直接从响应累计。

### 3.4 E3 修订探针（三臂统一，选做子实验）

各臂 v1 交付后，注入统一指令：「在不损失任何技术论断与引用的前提下，将全文压缩
至少 20%」。v2 产出后对齐 METRICS §3.4 口径算论断存活率。P 臂走
existing_paper_improvement 工作流（产品内既有旁路）；C/L 在原会话续跑。产物与
v1 同规归档。**探针不占主实验预算**，作为附加 run 标注 `probe=true`。

## 5. 产物捕获规范（每 run 目录）

```text
evaluation/runs/m10/<runId>/
  manifest.json          # §4
  inputs/                # 任务卡快照、P 臂 prompt 请求、C/L 会话导出
  outputs/               # main.tex、sections/、references.bib、paper.pdf(如有)
  transcripts/           # C 臂 stream-json、L 臂消息序列、P 臂 events.jsonl 副本
  telemetry/             # P 臂 AUDIT §3.7 全量文件副本（或指向 projects 快照）
  cost/                  # 差分快照对、usage 日志原片、价目表版本
  run-record.json        # METRICS §8
  v2/                    # E3 探针产物（如有）
```

P 臂 projects 数据在隔离 `PROJECTS_ROOT` 内原位保留至实验终结归档，然后按
**白名单清理**（只删本实验创建的 projectId 清单，禁止遍历删除——历史 QA 红线）。

## 6. 时间线与预算

| 项 | Pilot | Main | 说明 |
| --- | --- | --- | --- |
| runs | 9 | 36-48 | 串行 |
| 机器时间 | ~8h | ~40-60h | 锚：P 臂 35-45min（M9.7.1）；C/L 待 P0-5 实测 |
| API 成本 | ~$30-50 | ~$150-300 | P 臂 $3.5/run 锚；C 臂单 run 成本是 P0 重要产出 |
| 人工 | gold 3 任务×2人×1h；盲评 3 任务×3人×1.5h | gold 累计 6-8 任务；盲评 6-8 任务 | 盲评见 HUMAN_EVAL |
| 日历 | 1 周 | 2-3 周（串行+失败重试缓冲） | |

## 7. 风险与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| C 臂接网关不稳/被限流 | 中 | P0-1 冒烟；串行+间隔；request id 留痕；必要时降级模型（登记混杂） |
| P 臂 run 失败（M9.7.1 run1 先例） | 中 | 重试 1 次；DNF 如实计数进可靠性结论 |
| 三臂产物格式不齐 | 高（首轮） | P0-3 迭代任务卡模板；中性 deliver 追加一次 |
| 天花板效应（C1 全 1.0） | 中 | METRICS §7-5 预注册降级路径 |
| 盲评泄漏（认出系统） | 中 | HUMAN_EVAL §5 匿名化清单 + 猜测测验 |
| 评估自身 bug | — | run-record 生成器带 schema 校验（M6.8「脏数据拒绝运行」纪律） |

## 8. 报告纪律（与 M6.8 对齐）

- JSON 事实源 + Markdown 人读解读，数字不做手工修饰；
- Limitations 强制段：样本量、单网关混杂、judge/人工信度、DNF 口径；
- 结论措辞按证据强度分级：「机制层（M6.8 已证）」/「方向性证据（pilot）」/
  「配对显著（main, Holm 校正后）」；
- 全部原始 run 目录随报告入 Git（ transcripts 大文件按仓库现状裁量，至少
  run-record + manifests + 产物入 Git）。
