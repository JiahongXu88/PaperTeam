> 日期：2026-09-25 · 里程碑：M10.0（Evaluation Framework Design，Phase 0）
> 性质：**只读审计**，零代码改动（审计基线 `main` @ `9fb94b7`，working tree clean）。
> 方法：4 路并行代码审计（Research / Evidence / Writing-Review-Revision / 运行基础设施），
> 交叉核对既有评估报告（M6.8 / M6.9.x / M9.7.1）。

## 1. 全局事实（评估者必须先知道的三件事）

1. **无数据库，纯文件**：全 backend 无 SQLite/任何 DB（`project/ProjectStore.ts:13` 明示
   「不引入数据库」）。所有持久化是 `PROJECTS_ROOT/{projectId}/` 下的 JSON/JSONL/LaTeX
   文件（目录集 `ProjectStore.ts:111-120`：`manuscript/ sources/ evidence/ reviews/ build/
   workflow/ research/ artifacts/`）。**对评估是好消息**：一次 run 的全部记录可直接从
   文件系统离线收割，无需要求系统新增导出接口。
2. **评估框架已存在且有纪律**：`backend/src/evaluation/`（M6.8）+ live/multiModel 扩展
   （M6.9.x），统一入口 `npm run evaluation`，报告 JSON 事实源 + Markdown 摘要入 Git
   （`evaluation/reports/`）。M10.0 的定位是**它的下一阶段扩展**（整篇论文 × 真实基线
   对照 × 人工盲评），不是另起系统（POST_M8 §D 决议维持）。
3. **LLM 调用层遥测不落盘**：token/费用/逐调用时延只存在于进程内存
   （`PiRuntimeAdapter.ts:2585-2611`、`runtime/types.ts:229-240`）与一行 stdout 日志
   （`PiRuntimeAdapter.ts:2610-2616`），重启即失。这是成本指标的唯一阻断性缺口（§7-G1）。

## 7. Gaps 清单（按对 M10.0 的阻断性分级）

**A 级（阻断某类指标，须在协议中设计绕行；M10.0 红线 = 不改产品代码）**

- **G1 token/费用不落盘**：Per-run usage 仅内存 + stdout。绕行（评估框架侧实现，属
  M10.1 实现项）：① 运行期轮询 `GET /api/runtime/status` 做差分（liveExp1 先例）；
  ② 抓取并解析 `[pi-runtime] usage` 日志行（M9.7.1 先例）。两者都不需要改产品。
- **G2 Agent 自发搜索无持久日志**：非计划通道的 `search_papers`/`search_web` 调用无法
  事后审计。影响 Research 层「检索行为」指标在 Arm P 侧的完整性；绕行：协议限定 Arm P
  走「先批准计划再执行」的受控循环形态（M8.4 语义），使全部检索走 executionHistory。
- **G3 模型身份不入 checkpoint**：绕行：run 前后各拍一次 `/api/runtime/status` 存档；
  协议层记录 `{spec, source, 快照时间}` 入实验 manifest。

**B 级（指标降级或需离线重算，不阻断）**

- G4 核验漏斗逐段通过非一等字段（靠 statusReason 字符串解析）——口径脆弱性登记。
- G5 Writer 无字数、无逐节 citation key 记录——均可由 `sections/*.tex` 离线机械重算。
- G6 覆盖分析不落盘、无 coverage 百分比字段——评估侧自行算比率。

- G8 events 导出仅 SSE——直接读文件系统即可。
- G9 m97x 系列驱动脚本 gitignored——M10.1 实现时按文档口径重建（串行/隔离栈/清场纪律
  已在报告中有文字记录）。

## 8. 对后续设计文档的输入约束（结论）

1. **产物级指标全部可采**：三臂最终交付物（LaTeX/PDF + 引用表）+ Arm P 的全量落盘
   记录，足以支撑 M10.0 全部六组指标（Research/Evidence/Citation/Writing/Revision/
   Cost）——前提是基线臂也被要求交付**同构产物**（LaTeX 源 + references.bib），这成为
   任务卡硬约束。
2. **跨臂公平性要求外部统一核验**：PaperTeam 内部报告（claim-grounding / citation-
   report）**只作 Arm P 内部遥测**；主指标一律由评估侧统一核验器对三臂产物重算。
3. **成本采集是工程量最大的缺口**（G1/G3），协议必须为三臂各自定义同口径的 token/
   time/money 采集法（Arm C 有 stream-json 转录、Arm L 有 API usage、Arm P 用差分/日志）。
4. **评估基建归位**：新实验驱动/采集/核验代码统一进 `backend/src/evaluation/`
   （POST_M8 §D 决议），M10.0 只交设计，实现属 M10.1。
