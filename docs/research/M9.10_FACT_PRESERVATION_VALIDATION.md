## 1. Phase 1 — Revision Protocol Stability

### 改动

| 文件 | 内容 |
|---|---|
| `backend/src/review/revisionItemStatus.ts` | ① `RevisionProtocolError`（结构化错误：`code` ∈ {duplicate_conflict, illegal_transition, unknown_item, duplicate_item_id, invalid_item_status, missing_transition} + `violations[]`，message 保持旧口径）；② `validateRevisionPlanShape(plan)`：计划本体重复条目 id / 非法 status 确定性拒绝；③ `findStuckAppliedItems(plan)`：缺失 transition 检测（validate 后仍停留 applied = 编排跳步）；④ `applyRevisionItemTransitions` 入口先过计划 schema 断言 |
| `backend/src/review/revisionPlan.ts` | `buildRevisionPlan` 构建期后置断言：多通道合流（external/finding/citation/fact/build/gate）产出非法 schema 即抛 `RevisionProtocolError`，不落盘坏计划 |
| `backend/src/workflow/definitions.ts` | `revision.validate` 落定后检查 `findStuckAppliedItems` → 非空抛 `missing_transition` 结构化错误（原先条目会无声悬置，gate 只消费 validation result 看不到计划残留） |

### 语义

- **重复 transition**：M9.7.6 的归一化（幂等 collapse / 合法路径 replay / 矛盾拒绝）保留；矛盾拒绝现在携带结构化 violations，不再只是裸字符串。
- **重复 item id**：在计划构建期与流转入口双层拒绝（审计 §2.4-G2）。
- **非法状态跳转**：既有状态机口径不变，错误升级为结构化（§2.4-G1）。
- **缺失 transition**：新增检测（§2.4-G3）——派发了执行但没走到任何复核终态的条目显式暴露。

## 2. Phase 2 — Citation Preservation Hardening

### 改动（`backend/src/writer/WriterService.ts`）

- `renderCitationFreezeLines(currentLatex)`：修订 prompt 新增 **第 11 条引用冻结清单**——本章节当前实际引用的 key 由 `extractCitationKeys` 确定性提取（非 LLM 推断），显式列出 + 四条硬规则：
  - 禁止删除清单内任何 key（不得因「证据不足」「精简」「重写」「B 组身份」移除）；
  - **弱化论断 ≠ 删除引用**（弱化后的表述仍带原 \cite）；
  - 只有修订计划条目明确要求删除（如 citation_missing）才允许移除；
  - 允许新增 A 组 key。
- 依据（审计 §7）：M9.7.1 证明显式清单（A/B 组）有效（hallucinated=0）而隐式「保留原文 cite」在整节重写下概率性丢失——本修复把隐式约束变成显式锚点。
- 确定性拦截链保持并增强可解释性：`citationPreservation.unexpectedRemoved` → `citation_removal_unauthorized`（reasonCode，evaluation runner 对账口径不变）→ **category `citation_removal_detected`**（M9.10 事件名）→ revision_validation rejected → HITL。授权删除仍只承认四种结构化依据（planned_citation_missing / planned_explicit_mention / planned_evidence_removal（全位置覆盖）/ improvement_plan_explicit_mention），catastrophic 全删规则与历史回归规则不变。

## 3. Phase 3 — Fact Preservation Hardening（分类 + false positive 消除）

### 改动（`backend/src/quality/factPreservation.ts`）

- **数值等价归一** `normalizeNumericToken`（只用于相等性判定与授权匹配）：全角→半角、千分位剥离（1,446 ≡ 1446）、Unicode 减号统一、小数尾零剥离（45.90 ≡ 45.9）、单位字母小写（3.31FPS ≡ 3.31fps）。
- **全角数字提取前预归一**：２０２２ 原本进不了 `\d` 提取器（伪装成删除类 FP）。
- **四类分类**（每个 `FactFinding` 携带 `classification {category, type, severity, oldValue, newValue}`）：
  - **A 明确事实变化**（high，违规）：数值漂移 / 删除 / 新增 / 方向反转 / 公式 / 占位 / 协议——判定口径与 M5.6 完全一致；
  - **B 格式变化**（low，非违规）：数值等价的写法差异 → 新桶 `formatChanges`（审计轨迹，不参与 ok）；
  - **C 语言重写**（medium，非违规）：数字未动、周边措辞变（表格单元格路径）；
  - **D 引用范围变化**（low，非违规）：差异只在 \cite 参数（由 Citation Preservation 独立裁决）。
- **授权匹配跨格式**：`mentionsValue` 增加归一化通道 + 数字核心通道（token 带单位后缀「1446条」时用「1446」匹配计划文本「1,446」）——授权 miss 即保守 FP，本通道只减少 miss。
- `describeFactPreservation`：通过/失败都呈现格式等价计数。

### 严格程度声明

A 类（真实数值漂移）的检测逻辑、授权口径、gate 规则零改动；B/C/D 只在**数值可证等价**（归一化后相等 / 数字多重集相等 / 差异仅在 cite 参数）时豁免。既有 27 个 factPreservation 用例（含 45→28、35.9%→38.7%、方向反转、占位回归等 FAIL 场景）全部保持通过。

- 测试稿：自建中文 LaTeX 论文（4 节 + 8 key references.bib，**故意使用 M9.7.1 被删的 7 个 key**：besta2024graph / boiko2023autonomous / hong2023metagt / huang2023large / qin2024tool / yuan2024judge / zhou2023webarena），含表格（延迟/帧率/内存）、公式、方向性结论（低照度负结果）。
- 注入 3 条外部修改意见（`POST /external-instructions`，确定性输入通道）：

### 6.3 E2E 发现的新问题（已修）

**PT-OUTCOMES 协议行泄漏**：无外部意见派发的修订目标上，GLM-5.3 自发输出协议行——把 RevisionPlanItem id 当 instructionId 上报（rev3 实录三处：experiments/method/conclusion）。`splitExternalOutcomes` 只在派发过外部意见时分离，泄漏行连 JSON 进入正文，其中数字片段（verified=0、id 尾串）被 Fact Preservation 正确判为 `added_number` A 类违规 → 拦截链生效，但也污染了稿件。

修复（Phase 1「Writer 输出 schema 强化」收口）：`WriterService.reviseSection` 输出统一过 `stripStrayOutcomeLines`——协议标记行不可能是合法 LaTeX 内容，无论是否派发过外部意见都防御性剥离；新增单元测试（无派发剥离 / 派发时合法报告行仍正确分离且 outcomes 解析不受影响）。

> 时序说明：E2E 的运行 dist 含 Phase 1–4 全部修改，但不含本修复（运行中发现后落地）。该修复经 1741 项单元测试验证；E2E 中该缺陷的**拦截路径**（fact gate 检出 → validate rejected → build 阻止）已由本次运行实证。

### 6.4 诚实边界

- 本次 run 以 `failed`（FACT_PRESERVATION_FAILED）终态收口——这是门禁**正确**阻止污染修订产出 Draft，不是回归；同等场景在 M9.7.1 是 HITL 人为放行。
- revision success rate 33% 反映的是真实违规（越权删表、协议泄漏），非误判；修复协议泄漏后预期显著上升（未重跑全链路验证该预期——成本考量，如实记录）。
- 测试稿自身数值有口径瑕疵（901.5ms 与 3.31FPS 非倒数关系），被 Writer 在 conflict 依据中指出——不影响三案例判定。
