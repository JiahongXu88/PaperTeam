> 2026-09-22 完成态报告。前置：M9.1 PASS（`19b9ac4`）、M9.2 PASS（`0f48018`）、
> M9.3 PASS（`5240dec`）、M9.4 PASS（`27cb5c0`）。本阶段目标：把 M9.4 打通的
> Verified Evidence 链路延伸到论文引用侧——**Verified Evidence → Canonical
> Metadata（SourceIdentity）→ 确定性 Citation Key → Writer `\cite{}` →
> references.bib** 全闭环。分工纪律：LLM 只负责论文内容与引用意图；**metadata

## 1. Existing Bibliography Audit（静态审计结论）

以 main `27cb5c0` 源码为准。审计范围：`backend/src/citation/`（CitationService /
StaticCitationChecker / referenceText / …）、`sources/`（SourceStore / identity /
bibtex）、`manuscript/`（ManuscriptService / LatexFiles）、`writer/`、
`evidence/`、`quality/`（evidenceCitationCoverage / gates）、workflow definitions、
ResearcherService、全部既有测试。

- **bibliography 生成点**：ResearcherService（LLM）在调研 JSON 中输出
  `bibliography` 数组（`readBibliography` 解析），存 `research/research.json` →
  `ResearchArtifact.bibliography`；`outline.plan` 阶段调
  `ManuscriptService.writeBibliography`（definitions.ts）渲染 references.bib。
- **BibTeX 来源**：混合、LLM 主导——LLM 发明条目字段与 key；代码只做渲染
  （`renderBibEntry` 恒 `@article`、venue→journal、无 LaTeX 转义、无 arXiv 语义）。
- **citation key**：LLM 按 prompt 规则 5「第一作者年份主题」自造；代码仅 regex
  校验 + 精确去重。非确定：同文献跨 run 可得不同 key；**无同作者同年冲突消解**
  （两篇可撞 key 静默丢一条）。
- **Writer `\cite` 决策**：纯 prompt 约束（规则 3/4「优先行内 cite 标注 +
  只允许引用给定 key」）；`renderEvidenceLines` 经
  `EvidenceSelectionService.matchBibliographyKey`（DOI→归一标题+年份）从 LLM
  bibliography 反查，失败则无标注。
- **references.bib 生命周期**：outline.plan 一次性写入**全部** artifact 条目
  （含未引用）；writing.sections 不更新；修订路径只读合并
  （`manuscriptBibliography`）。
- **EvidenceRecord 元数据**：`EvidenceSourceRef { sourceId?, title?, authors?,
  year?, doi?, url? }`——有 DOI/title/authors/year/url，无 arxivId/venue（后者
  只在 SourceStore）。
- **SourceIdentity 足够性**：identity 本身（doi/arxivId/pmid/标题指纹+年份+一作/
  url）不足以渲染（缺全作者、原始 title、venue），但 `SourceItem = identity +
  metadata + versionType` 完整覆盖 article/inproceedings/misc——无需第二套
  metadata。
- **既有三函数全部复用**：`matchBibliographyKey`（降级为 fallback）、
  `manuscriptBibliography`（保留「allowed keys 必须覆盖稿件已有 key」教训，
  2026-09-14 真实论文验收 B2/A2）、`computeEvidenceCitationCoverage`
  （升级 sourceId 优先匹配）。

## 2. Why LLM-generated Citation Is Insufficient

1. **非确定**：同一文献跨 run 产生不同 key（`zhang2024survey` /
   `zhang2024rag`），修订轮与重跑轮之间引用表漂移；
2. **无冲突消解**：同作者同年两篇可撞 key（readBibliography 精确去重静默丢
   一条）或任意分叉；
3. **元数据幻觉面**：LLM 回忆的年份 / venue / DOI 未经 SourceIdentity 判等
   直接进入 references.bib——与 M6 起的 Retrieved ≠ Verified 纪律矛盾；
4. **Evidence 追溯断裂**：Evidence → key 靠 DOI/标题模糊反查 LLM 条目，LLM
   条目常缺 DOI → 反查失败 → 证据有但 prompt 无 cite 标注；
5. **引用表膨胀**：references.bib = 全部调研条目，与「实际引用」脱钩。

M9.5 的回答：key 与渲染是**纯函数**（同输入必同输出），LLM 的 bibliography
字段降级为「引用意图 + 元数据回忆」的输入素材，同身份条目被文献库
authoritative metadata 覆盖，其余条目确定性重 key。

## 3. SourceIdentity → BibliographyEntry（数据边界）

新模块 `backend/src/citation/bibliography.ts`（唯一事实源，纯函数零 I/O）：

```
SourceItem（identity + metadata + versionType）┐
                                              ├→ BibliographySeed（判等键 + 最小投影）
ResearchArtifact.bibliography（LLM 引用意图）  ┘        │
                                                       ▼
                                            assignCitationKeys（去重 + 冲突 a/b）
                                                       │
                                                       ▼
                                        CanonicalBibliographyEntry
                                          { key, type, title, authors?, year?,
                                            venue?, doi?, url?, arxivId?,
                                            sourceId?, identityKey, origin }
                                                       │
                                       ┌───────────────┴───────────────┐
                                       ▼                               ▼
                            renderBibliographyFile            resolveEvidenceCitationKey
                            （references.bib 字节）            （Evidence → key，使用点解析）
```

- **不复制第二套 metadata**：seed 只取渲染所需字段；EvidenceRecord 上**不存**
  citationKey（那是复制）——追溯在使用点经 `sourceId` 解析；
- **type 推导**：versionType conference→`inproceedings`、journal→`article`、
  preprint→`misc`；缺省按 venue 有无 → article/misc。刻意只覆盖三类，不做全
  BibTeX 类型系统；
- **去重**：同 identityKey 的 LLM 条目丢弃（source-library 条目 authoritative
  胜出）。

## 4. Citation Key Strategy

`baseCitationKey({authors, year, title})` = **一作 family + 年份 + 首个有效标题词**
（如 `vaswani2017attention`、`gao2023retrieval`）：

- family 取 `identity.ts firstAuthorFamily`（BibTeX "Family, Given" 与自然序
  均可），NFKD 后仅保留 `[a-z0-9]`（中文等非 ASCII family 优雅降级为标题词）；
- 标题词取 `canonicalTitleTokens` 首个 ≥2 字符且非功能词（on/the/of/for/…）
  的 ASCII token；
- 年份缺失 → `nd`；作者与标题全缺 → `source` 兜底（graceful fallback）。

**冲突消解（deterministic）**：`assignCitationKeys` 对 seed 集合按基础 key 分组，
组内按 identityKey 排序，首条用裸 key、其后追加 `a/b/c…`（base26，wang2024 →
wang2024a → wang2024b）。**同输入任何重算（含打乱输入顺序）得到完全相同的
key 集合**——这是「同一个 SourceIdentity 永远产生同一个 key」的实现口径：
key 是 bibliography 集合状态的纯函数。

已知边界（§13）：向集合**新增**一条同基础 key 且 identityKey 排序更前的来源
时，组内后缀会重排（a/b 互换性质）——不持久化 key 的代价，换来零 migration
与重建自由；运行内（outline → sections → 修订）文献库稳定，跨阶段一致由
「每次全量重算 + references.bib 整体重渲染」保证。

## 5. BibTeX Renderer

`renderBibEntry` / `renderBibliographyFile`（citation/bibliography.ts）：

- **字段顺序固定**：author → title → journal/booktitle/howpublished（按类型）→
  year → eprint + archivePrefix={arXiv} → doi → url → **sourceId**（追溯字段，
  BST 忽略未知字段、不影响编译；`StaticCitationChecker.parseBib` 回读它）；
- **作者归一**："Given Family" → "Family, Given"；单 token（中文姓名）原样；
  `and` 连接；
- **LaTeX 转义**：`& % $ # _ { } ~ ^ \` 七类字符；年份为数字不转义；
- **文件级**：按 key 排序、`\n\n` 连接、末尾单换行；空集 → 空文件（无 \cite
  可编译）。**同输入字节级一致**（无时钟 / 随机 / locale 依赖——比较用
  codepoint 序）。

`ManuscriptService.writeBibliography` 保留原签名语义（entries → 条数），渲染
下沉到上述模块；重复调用 byte identical（幂等重写）。

## 6. Evidence → Citation Trace

`resolveEvidenceCitationKey(record, entries)`（不落存储）：

1. `record.source.sourceId` 精确命中 `entry.sourceId`（确定性渲染写入的追溯
   字段）→ 直接返回 key；
2. 降级复用 `EvidenceSelectionService.matchBibliographyKey`（DOI → 归一标题
   +年份）——单一匹配口径不分裂；
3. 无匹配 → null（调用方不标注、不猜测）。

消费点：
- **WriterService.renderEvidenceLines**：`[E001]（cite: gao2023retrieval）claim…`
  ——Writer 在 prompt 里直接看到每条 formal evidence 对应的确定性 key；
- **quality/evidenceCitationCoverage**：`citations_evidence_backed` 规则升级为
  sourceId 优先（`BibEntrySummary.sourceId` 由 parseBib 回读）——gate 报告的
  覆盖判定与 Writer 引用标注同源。

只有 **formal evidence**（verified + sourceId + chunk 三件套，
EvidenceSelectionService 规则）进入该通道——legacy unverified 不产生 cite
标注、不算覆盖来源（M6.6 使用策略延续）。

## 7. Writer Integration（不重写 Writer）

- `buildSectionPrompt` / `buildOutlinePrompt` / `buildRevisePrompt` 结构不变；
  「只允许引用以下参考文献 key」列表的**来源**换成 canonical bibliography
  （workflow 侧 `buildCanonicalBibliography`）；
- 行内 `（cite: key）` 标注换 `resolveEvidenceCitationKey`（§6）；
- `scriptedRuntime` 同步升级：脚本化 Writer 镜像真实 Writer 纪律——cite key
  从 prompt 的 allowed-keys 行读取（`reciteToAllowedKeys`），不自造固定 key；
  修订/修复输出沿用「本章节当前内容」既有 key（与真实 Writer 的引用保持纪律
  一致）；
- Researcher prompt 规则 5 措辞更新：key 仅作占位（格式校验用），最终 key 由
  系统按文献身份确定性重排——LLM 输出 schema 不变（legacy 兼容）。

## 8. references.bib Lifecycle

- **outline.plan**：写入完整 canonical bibliography（此时无正文，谈不上裁剪；
  main.tex 的 `\bibliography` 开关据此判定）；
- **writing.sections / revision.revise / revision.repair_latex**：提交修订
  **之前**执行 `syncReferencesBib`——收集当前 manuscript 全部 \cite key
  （`collectLatexFiles` + `extractCitationKeys`），把 references.bib 重渲染为
  canonical ∩ cited。**只含实际引用文献**；幂等（同输入 byte identical）；
- **调用时机纪律（集成测试暴露的真实 bug）**：bib 同步必须与正文变化落在
  **同一个修订号**里。最初放在 citation.verify（修订 commit 之后、review 快照
  之前）会在修订与快照之间制造额外修订号，使 Citation Preservation 的
  rev(n-1)→rev(n) 比较跳过真正的引用丢失轮（回归见
  deterministicBibliography 集成测试 + citationPreservationGate 复跑）；
- **用户数据红线**：`syncReferencesBib` 守卫 `isExistingPaperKind(project.
  workflowKind)`（PDF / LaTeX 导入项目 ProjectImport 必写 workflowKind）——
  Existing-Paper 的用户 references.bib 任何情况下不改写（集成测试：导入项目
  全流程后用户 bib 逐字节保持）。

## 9. Legacy Compatibility（零 migration）

- 旧 research.json 的 LLM bibliography：照常读取，进入 canonical 时确定性重
  key（同身份条目被文献库覆盖）——旧项目重跑 outline.plan 即切换到确定性
  引用表，不迁移不重写存量数据；
- 旧 Evidence（unverified / 无锚点）：保持原样，不进入正式 citation pipeline
  （selectForWriting formalOnly + evidence_query writer 视图双重结构保证）；
- 旧 references.bib（用户 / 导入 / M9.5 前生成）：修订与润色路径的
  `manuscriptBibliography` = canonical ∪ **references.bib 现存条目**——稿件里
  已有的 key 永远在 allowed 列表（2026-09-14 B2/A2 教训保持）；
- Existing-Paper / PDF 重建项目：references.bib 不被系统触碰（§8 守卫）。

## 10. Academic / Web Boundary

M9.5 只处理**学术文献**的 BibliTeX 化（SourceStore 条目 + LLM 学术引用意图）。
Web 来源（M9.2 SearXNG 候选）：url-only 候选本就不产生 chunk、不进锚定路径
（M9.4 §11 结构边界）；本阶段**不把普通网页强行变 Academic BibTeX**——
artifact 条目里的 web 线索按 misc 渲染（有 url 无 venue），不给伪造的
journal/booktitle。Web 正文引用是后续独立设计，本阶段不扩展。

## 14. Known Limitations

1. **冲突后缀的跨集合稳定性**（§4）：新增同基础 key 来源可重排组内 a/b 后缀；
   运行内一致，跨增长重排由「references.bib 每次整体重渲染 + gate 重算」吸收
   （旧正文若引用了重排前的 key，citation_structure_valid 以 missing key 如实
   暴露）。持久化 key 索引（manuscript/bibliography.json）是后续可选项，本阶段
   按「不复制第二套 metadata」纪律不做。
2. **非 ASCII 作者**：中文一作降级为标题词段（`[a-z0-9]` 约束来自 cite key
   合法字符集）；中文姓名的拼音化需要 transliteration 表，刻意不做。
3. **artifact 条目元数据未经核验**：LLM 回忆的 venue/年份进入 misc/article
   渲染（如实，不伪造更强字段）；后续可接 scholarly enrich（复用
   SourceImportService 通道）。
4. **`sourceId` 字段是 PaperTeam 扩展**：标准 BST 忽略之（编译无影响），但导出
   给外部工具时会多一个未知字段。
5. **修订路径的 allowed keys 仍含 canonical 全集**（未裁剪）——修订期 Writer
   可引用尚未出现在 references.bib 的 canonical 条目，下一轮 sync 会把它补进
   引用表；这是特性（引用表随稿件演化）不是缺陷，但意味着 references.bib 的
   「最终态」以最后一次内容提交为准。
6. **EC006 类 judge 解析失败**（live smoke run 1 实测 1/8）：unverifiable 如实
   记录，不阻塞、不伪造；属 M6.5 既有语义。
7. **本机 PDF 参考文献渲染空**（§13 工具链问题）：Git-Bash perl + MiKTeX
   latexmk 的 BIBINPUTS 路径形态冲突——**环境级问题、影响任何 bib 构建**（含
   Existing-Paper 导入项目），非 M9.5 引入；references.bib 文件本身经本地
   bibtex 验证可正确解析。**已由 M9.5.1 修复（§17：LatexCompiler 弃用
   latexmk，xelatex + bibtex 显式编排 + staging 统一工作目录）**。
8. **UI 无 .tex / references.bib 文件浏览器**：引用链的 UI 可见面是概览页
   「参考文献 N 条」+ 工作流时间线 citation.verify + Evidence 页锚定标注；
   .tex / bib 原文核对走磁盘产物（验收保留在 e2e/.tmp 下）。文件查看器是
   M9.6 候选增强，不属本阶段。

## 17. M9.5.1 — LaTeX Bibliography Toolchain Fix（渲染链修复）

范围纪律：只修 LaTeX → BibTeX → PDF 渲染链；Citation Model / Evidence
System / Writer Logic / Bibliography Design（key 算法、renderer、prompt）
一律未动。

### 17.1 Issue（现象与定位）

references.bib 本身三层验证全过（deterministic render / bibtex parse /
citation.verify），但最终 PDF 的参考文献列表为空、正文引用无编号——
且编译 exit 0，Build Gate 不拦（事故 PDF 见
`e2e/.tmp/acceptance/stack-m95/.../build/paper.pdf.m95-broken-backup`：
7 页、0 编号引用、0 条目）。

最小复现（本机）证实问题出在 latexmk 触发的 bibtex 步骤：

- `main.blg` 显示 `Database file #1: references.bib` 打开后
  `Warning--I didn't find a database entry for "…"`（逐条）且
  `You've used 0 entries`——**bibtex 打开的是错误的 references.bib**，
  不是 manuscript/ 里那份。

### 17.2 Root Cause（双重根因）

1. **latexmk 委托 MSYS perl（环境级，§13 已记录）**：Windows 上 MiKTeX
   `latexmk.exe` 是 perl 包装脚本，委托 PATH 中的 perl（开发机唯一 perl 是
   Git-Bash MSYS 构建）。其运行时把 `BIBINPUTS` 写成 `/d/...` MSYS 路径
   形态，Windows bibtex 无法据此定位 cwd 的 bib，转而打开 BIBINPUTS 默认
   搜索路径下的同名文件 → 0 entries → 空 references，latexmk 仍 exit 0。
2. **fallback 单轮编译（代码级，审计新发现）**：xelatex fallback 路径只有
   一轮编译，结构上永远不触发 bibtex / 多轮——即工具探测落到 xelatex 时
   references 必然缺失，且无任何报错。

### 17.3 Fix（单一方案：显式编排 + staging 统一工作目录）

`backend/src/latex/LatexCompiler.ts` 重构（不引入 latexmk 修复补丁、
biber、tectonic、WSL 等第二方案；不设任何环境变量；不硬编码路径）：

- **弃用 latexmk 委托**：工具链 = 原生 `xelatex` + `bibtex`（MiKTeX /
  TeX Live / WSL 发行版标配；不经过 perl）；
- **staging 统一工作目录**：编译前把 manuscript/ 全部源文件复制进
  build/，编排命令全部以 buildDir 为 cwd、不用 `-output-directory`——
  tex / bib / aux / bbl 同目录，bibtex 天然读到正确的 references.bib，
  xelatex 天然读到 main.bbl；manuscript/ 源目录零污染；重复 build 前
  按扩展名白名单清理旧 TeX 产物（输出一致）；
- **编排**：xelatex（pass1，产 aux）→ aux 含 `\bibdata` 时 `bibtex main`
  → xelatex × 2（渲染 bbl + 解析编号）→ main.log 提示 Rerun 最多追加
  2 轮（固定上限）；全程共享 compileTimeoutMs 预算（deadline 模式，
  语义与原单命令超时一致）；每步非零退出立即失败；
- **三道显式化检测**（让「references 空」不可能再静默通过）：
  1. bibtex 非零退出 → `LATEX_COMPILE_FAILED`（detail 含 exitCode）；
  2. `.blg` 报 `used 0 entries` 且 aux 有 `\citation` → 失败（M9.5
     事故形态的直接回归检测）；
  3. 最终 main.log 仍有 `Citation … undefined` → 失败（natbib 未解析）；
- **Rerun 措辞统一匹配 `Rerun to get …`**：实测 natbib 用
  `Rerun to get citations correct`（非 LaTeX 的
  `…cross-references right`），只匹配后者会漏判 → 提前收敛 → 引用未
  解析（该缺陷由上述检测 3 在 smoke 中当场拦截后修复）；
- 接口不变：`compile({manuscriptDir, buildDir})` 签名、`LatexCompileResult`
  结构保持；`tool` 语义变为 `"xelatex+bibtex"` / `"xelatex"`；
  `detectTool()` 返回同名描述（readiness 兼容）。

配套：e2e fakebin 由 fake latexmk 换为 fake xelatex + fake bibtex；
4 处测试 fake runner（testStack / httpServer / repairLoop / evaluation
harness）同步改为 cwd 模式；Dockerfile 保留 latexmk 包（手动构建可选）
但 CI/Docker 探测验证改为 xelatex + bibtex；readiness / errors / README /
ARCHITECTURE / DEPLOYMENT 文案同步。
