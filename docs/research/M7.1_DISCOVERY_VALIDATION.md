## 2. 测试问题（三个场景）

| 场景 | 输入（原样） | 观察目标 |
|---|---|---|
| A 新领域文献调研 | 「调研2024-2026年基于Transformer的多目标跟踪方法，总结主要研究方向和代表论文」 | ① 调用 search_papers ② 返回 Candidate Sources ③ 调用 save_candidates ④ CandidateStore 产生记录 |
| B 事实验证 | 「ByteTrack发表于哪一年？它解决了什么问题？」 | 优先检索验证（search_papers / lookup_paper），不依赖模型记忆 |
| C 已有论文分析 | 「分析我的论文算法还有哪些改进方向」（analyzeExistingPaper + 结构化论文摘要） | 不强制搜索；项目上下文足够时允许直接分析 |

场景 A/B 走 `ResearcherService.research`（research.idea 主链路 prompt）；场景 C 走
`ResearcherService.analyzeExistingPaper`（existing-paper 论文理解 prompt）。

## 3. Tool call 记录（真实事件流，seq 为任务内单调序号）

### Scenario A（242.6s · 15 assistant turns · 24 次工具调用 · 0 错误）

| 阶段 | 调用序列（start/end 对计 1 次） | 说明 |
|---|---|---|
| 多轮检索 | search_papers ×9（seq 479/792/1077/1345/2572/3942/4043/4153/4412） | 自主多角度 query：`Transformer multi-object tracking`、`end-to-end query-based multi-object tracking`、`LiDAR point cloud 3D multi-object tracking`、`open-vocabulary multi-object tracking…`；含并行成对调用（seq 479+480 等）；携带年份聚焦（结果全部 2024-2025） |
| 批量保存 | save_candidates ×11（seq 3498 起批量 7 连发 + 后续检索-保存交错 4 次） | kind=academic + query 与检索时一致，按下标选取 |
| 核验/库工具 | lookup_paper / retrieve_library 0 次 | 文献库为空，未空转调用——工具选择与场景匹配 |

### Scenario B（106.9s · 4 assistant turns · 6 次工具调用 · 0 错误）

| 调用 | 说明 |
|---|---|
| search_papers ×2 + lookup_paper ×3（并行发起） | 对 ByteTrack 先检索再逐条核验：正式版（DOI 10.1007/978-3-031-20047-2_1）与预印本（arXiv:2110.06864）分别 lookup |
| save_candidates ×1 | 保存核验过的文献（6 条候选） |

**关键观察（检索优先成立）**：模型未凭记忆作答，最终答案明确写出——「arXiv 2021 年
10 月预印（arXiv:2110.06864），正式版 2022 年发表 ECCV（DOI 10.1007/978-3-031-20047-2_1），
经元数据核验确认为 2022 年」，并顺带核验 BoT-SORT（2022）。预印本/正式版作为
**两个独立身份**分别保存为候选（C001 2022 正式版 / C002 2021 预印本）——与
D-0034 分层身份键设计一致。

### Scenario C（103.4s · 3 assistant turns · 8 次工具调用 · 0 错误）

| 调用 | 说明 |
|---|---|
| lookup_paper ×3 + search_papers ×2 | **非强制、按需**：仅针对「与更强基线对比」类弱点时查证 ByteTrack/StrongSORT 等文献是否存在 |
| save_candidates 0 次 | 分析型任务未污染候选库（disk candidates = 0）——保存行为与场景匹配 |

**关键观察（直接分析成立）**：分析主体直接来自项目上下文（提供的论文结构化摘要），
产出的 weaknesses 全部锚定摘要中的事实（缺 ByteTrack 原始基线对比、ablation 未拆
MRG-DTM/ReID 贡献、HOTA 增益有限、运动项尺度失衡、INT8 与 ReID 嵌入矛盾），
未为满足检索而检索。系统层不强制：analyzeExistingPaper prompt 措辞为「可用」而非「必须」。

| # | 预设问题（任务书 Task 3 清单） | 是否出现 | 证据 |

| 1 | Researcher 不调用搜索 | ❌ 未出现 | 三场景全部主动调工具；A 场景 9 次自主多角度检索 |
| 2 | 工具调用失败 | ❌ 未出现 | 全部 tool_execution_end `isError=false`（38 次调用 0 错误）；SearXNG 未配置时 search_web 面未误用（A/B 均未调用 search_web） |
| 3 | 候选保存失败 | ❌ 未出现 | 21 条候选跨 12 次 save_candidates 全部落盘成功，含多 query 交错保存（进程内检索缓存按 query 定位在真实链路验证有效） |

**无预设外问题**。两条中性观察（不构成缺陷，记录备查）：

1. **B 场景保存 6 条候选**：简单事实核验型问题保存了 ByteTrack 系 6 条文献。
   在「≤20 条按相关性遴选」指引内、且全部与主题相关——属合理行为；若真实使用
   中发现事实型问题滥存，可在 prompt 收紧（留待真实使用数据，本轮不改）。
2. **A 场景 evidence 8 条为 abstract 级 quote 的 legacy unverified 条目**：
   检索结果的 abstract 片段被 Researcher 写入 evidence 字段（无 chunk 锚点 →
   unverified → 永不进 formal 池）。这是 M6.5 已知的兼容期路径，风险受控
   （三件套口径过滤），收口归 Researcher legacy 路径退役（M7.3 前评估）。

## 7. 最终结论

| 验证目标 | 结果 |
|---|---|
| Research Question → Researcher → Search Tool Calling | ✅ 三场景全部成立（A 9 次、B 5 次、C 5 次检索/核验调用，自主多 query） |
| Tool → CandidateSource 保存闭环 | ✅ 12 次 save_candidates / 21 条候选 / 全部 pending_review + provenance 完整 |
| 检索优先纪律（不凭记忆） | ✅ B 场景以 lookup 核验区分预印本/正式版并引 DOI，明确「经元数据核验」 |
| 不强制检索纪律 | ✅ C 场景分析主体来自项目上下文，仅按需查证，零候选污染 |
| 红线（HITL promote / 无 EvidenceStore 写路径 / 零新 Agent / 零 Runtime/Workflow 改动） | ✅ 全部维持 |
| 工具执行可靠性 | ✅ 38 次调用 0 错误；缓存 miss 路径未触发（全部命中） |

**结论：M7.1 Agent 侧链路（P-A + P-B 修复）在真实模型 + 真实公网检索上端到端
成立。** 「User Research Question → Researcher Agent → Search Tool Calling →
Candidate Saving → CandidateSource」全链路已验证；架构审查 §7.2-1 标记的最大风险
（「prompt 引导 ≠ 模型必然调用工具」）在本机 GLM-5.3 上证伪——模型行为与 prompt
约束高度一致。后续 M7.1 收口项：前端 Discovery & 候选管理 UI（P-C，冻结文档
§4-4）与全链路验收底线 1 的后半段（promote → 全文 → verified evidence 磁盘证据）。

**回归基线**：全量后端测试 1263 passed / 0 failed（11 skipped 为 live smoke，
与 M7.1a 收口口径一致）——本阶段零业务代码改动，测试零回归验证成立。
