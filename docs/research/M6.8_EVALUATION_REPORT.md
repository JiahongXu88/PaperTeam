## 2. Evaluation Framework 设计

```text
backend/src/evaluation/
  types.ts            共享类型（场景 / 臂结果 / 指标 / 报告 schema v1）
  datasets/           groundingScenarios(6) / revisionScenarios(7) /
                      workflowScenarios(5) / index(注册表 + 结构校验)
  metrics/            grounding / revision / workflow / calibration（纯函数）
  runners/            harness（评估栈）/ experiment1/2/3 / report / cli
scripts/evaluation.mjs  npm run evaluation 入口（dist 加载，先 build 后跑）
evaluation/reports/     生成的报告（JSON 事实源 + Markdown 摘要，入 Git）
evaluation/calibration/ 人工校准记录 records.jsonl（人工维护）
```

设计原则：

1. **不改被测系统**：评估只通过公开服务接口（EvidenceGroundingService /
   RetrievalService / WorkflowOrchestrator / quality 纯函数）驱动；评估
   代码独立于 backend/test（不 import 测试辅助）。
2. **确定性可重复**：全离线（无网络、无真实模型、无随机），同数据集同
   结果；语料自造（M6.4 benchmark 同风格）。两个确定性替身明确标注：
   GroundTruthScholarlyProvider（metadata 权威记录）、
   GroundTruthJudgeRuntime（Stage 3 语义 judge——唯一 LLM 阶段的替身，
   按 ground truth 返回 supported / unsupported）。
3. **故障注入单点复用**：Exp2 的三类 Writer 违规直接用 scriptedRuntime
   既有标记 `[fact:mutate]` / `[cite:drop]` / `[strength:escalate]`（src
   侧唯一事实源），baseline 臂由同一 `scriptedRevision` 物化——两臂只差
   「有没有安全机制」，不差注入实现。
4. **诚实失败**：数据集结构校验失败 → 拒绝运行；HITL 驱动超预算 →
   timedOut 如实上报；校准记录脏行 → malformed 计数不炸报告；Exp3 人工
   偏好无记录 → null（不伪造）；Exp1 处置与 ground truth 不一致 → issues
   + 非零退出码。

统一入口：`npm run evaluation [-- --experiment 1|2|3|all] [-- --scenario <id>…]
[-- --hitl-policy reject|approve|needs_review] [-- --out <dir>] [-- --list]`。

## 3. Dataset 设计

高质量小数据（任务复杂度优先于数量；全部确定性自造学术语料）：

| 实验 | 场景数 | 构成 |
|---|---|---|
| Exp1 grounding | 6 | 每场景 2-3 来源语料 + 2-3 正例 + 1-3 故障（g1 RAG 综述 EN / g2 多目标跟踪 ZH / g3 GNN EN / g4 语音合成 EN / g5 PPO EN / g6 中文情感分析 ZH） |
| Exp2 revision | 7 | 三类注入各 2（fact ×2 / citation ×1+zh 变体在 fact/strength 侧补齐 / strength ×2）+ 干净对照 2（fail→pass 单轮、fail→fail2→pass 多轮） |
| Exp3 workflow | 5 | 带语料干净 1（w1）/ 带语料修订环 1（w2）/ 无语料 legacy 1（w3）/ 中文语料 1（w4）/ 多轮收敛 1（w5）；每场景附代表性单次生成基线（缺陷如实标注） |

Ground truth 标注纪律：needle 逐字存在于语料（结构校验逐条验证）；
fabricated quote 必须不出现在任何语料；faultClass → 布尔三元组
（claimSupported / quoteVerbatim / metadataCorrect）确定性派生；
metadataCorrupted 来源必须声明不同的 authoritativeYear；正例不得锚定
损坏元数据来源（首轮实跑发现的数据设计错误——系统按设计正确拒绝、
是数据把正例标错——已修数据并加校验规则防再犯）。

## 4. Experiment 1：Evidence Grounding 是否降低错误？

**臂**（同一组 ground-truth 提案，只差系统配置）：

- **A plain-llm**：无文献库、无检索、无核验——提案按 LLM 自报直接入池
  （unverified；镜像 Researcher legacy 存储形态）；
- **B rag**：真实文献库 + 真实 RetrievalService——检索命中时 quote 被
  替换为检索 chunk 的逐字切片（RAG 生成条件化消除捏造引文），但零核验
  （元数据冲突 / 论断越界照单全收）；检索不命中（如跨语言无词重叠）时
  捏造照旧——**运行期实测，不是假设**；
- **C paperteam**：完整三段核验（quote 逐字 → metadata（ground-truth
  provider）→ 语义 judge（ground-truth runtime）），verified 才进正式
  证据池。

**注入**：fabricated_quote（quote 捏造但锚定真实 chunk）×5 /
unsupported_claim（quote 真实、claim 越界，如 38%→92%）×5 /
metadata_mismatch（存储年份与权威记录冲突）×2，共 12 故障 + 16 正例。

**一致性自检**：paperteam 臂处置与 ground truth 逐条核对（本轮 0 不一致）。

## 5. Experiment 2：Revision Safety 是否降低事实漂移？

**臂**：

- **baseline**：Reviewer → Writer，输出直接接受（无计划 / 验证 / 门禁）；
- **paperteam**：完整闭环 Reviewer → Revision Plan（条目生命周期）→
  Writer → Revision Validation（四类确定性复核）→ Quality Gate，由
  WorkflowOrchestrator 全链路驱动（与生产同一引擎）；HITL 策略默认
  reject（安全缺省：恢复修订前快照）。

**注入**：`[fact:mutate]`（公式常量 \alpha→\beta + 无依据数值 8.7%→12.4%）/
`[cite:drop]`（实验章节独有引用 \cite{lewis2020rag} 被删光）/
`[strength:escalate]（无数字支撑的「显著提升 / 显著优于现有方法」）+
干净对照（应零误拦）。

**观测**：revision-validation-r*.json（blocked / reasonCodes）、
quality-gate-r*.json（安全类规则）、HITL 序列、终稿 needles / 引用 key。

## 6. Experiment 3：Agent Workflow 是否比普通 LLM 更可靠？

**臂**：plain-llm（scenario 携带的代表性单次生成——捏造引用 key、无证据
数值论断、章节缺失等典型缺陷，作为 scripted 数据如实标注）vs
paperteam（完整 idea_to_paper：Research → Evidence.ground → Feasibility →
Outline → Writing → Citation Verify → Review → Revision → Gate → Build；
带语料场景 run 前预置 anchored 候选、经 evidence.ground 真实三段核验转正）。

## 7. Metrics

| 实验 | 指标 | 定义 |
|---|---|---|
| 1 | unsupported claim rate | 入池提案中 claim 越界占比 |
| 1 | fabricated citation rate | 入池提案中「quote 非逐字 或 元数据冲突」占比 |
| 1 | evidence coverage | 命中正例 / 场景正例总数（召回，拦错误不伤正例的度量） |
| 2 | fact/citation/escalation 存活率 | 违规内容出现在「被接受稿件」的场景占比（按注入类） |
| 2 | false acceptance rate | 注入违规且系统零信号放行占比 |
| 2 | false rejection rate | 干净对照被误拦占比（over-blocking） |
| 3 | claim correctness | 被引用论断可追溯到 verified evidence 的占比 |
| 3 | citation correctness | 输出 \cite key 非捏造占比（存在于该臂合法 bibliography） |
| 3 | completeness | stage 完成率 / 章节覆盖 / 论断 needle 覆盖 / 引用覆盖四项平均 |
| 3 | human preference | 校准记录 prefer-<arm> 占比（无记录 = null） |
| 校准 | agreement rate | 自动指标 prediction 与人工 humanLabel 一致率 |

聚合口径：Exp1 在 outcomes 层面按提案数加权；Exp2 按场景；Exp3 场景均值。
分母为 0 时返回 null（Exp2）或 0（Exp1/3 比率）——不伪造。

## 8. Results

### Experiment 1（6 场景 × 28 提案）

| arm | accepted | unsupportedClaimRate | fabricatedCitationRate | evidenceCoverage |
|---|---|---|---|---|
| plain-llm | 28 | 17.9% | 25.0% | 100% |
| rag | 28 | 17.9% | **7.1%** | 100% |
| paperteam | 16 | **0.0%** | **0.0%** | **100%** |

处置通道（paperteam）：accepted 16 / rejected_quote_mismatch 5 /
rejected_judge 5 / rejected_metadata_mismatch 2——三类注入故障全部在
对应阶段拦截（quote 逐字 ×5、语义 judge ×5、metadata ×2），正例 16/16
转正（coverage 无损）。

**结论 1**：Evidence Grounding 把注入类错误率降到 0 且不牺牲正例召回。
RAG 单独引入时消除了大部分捏造引文（25.0%→7.1%，残留 2 条均为 metadata
冲突——检索条件化管不到元数据），但对越界论断零改善（17.9% 持平——
引文真实 ≠ 论断被支撑，正是 Stage 3 语义 judge 补的位）。

### Experiment 2（7 场景，policy=reject）

| metric | baseline | paperteam |
|---|---|---|
| factViolationRate | 100% | **0%** |
| citationLossRate | 100% | **0%** |
| claimEscalationRate | 100% | **0%** |
| falseAcceptanceRate | 100% | **0%** |
| falseRejectionRate | n/a（基线无信号概念） | **0%** |

逐场景（paperteam）：5 个注入场景全部 completed/**final**——
`revision.validate` 以正确原因码拦截（fact_preservation_violation ×2 /
citation_removal_unauthorized ×1 / claim_strength_escalation ×2）→
`hitl.revision_validation` → reject 恢复快照 → 复审通过 → Final
（违规内容随 restore 消失，lewis2020rag 回到终稿）；2 个干净对照零误拦、
直达 Final。

值得记录的分层事实：所有 gate 轮的安全规则均 PASS——**拦截点前移到了
revision.validate**（M6.7 设计：修订写入后、复审前的确定性复核先于 gate
消费），故障修订从未到达 gate；gate 作为后备层在本轮数据上未被触发。

**结论 2**：Revision Safety 闭环把三类注入违规的存活率与零信号放行率
从 100%（baseline 直通）降到 0%，且干净修订零误拦（over-blocking = 0）。

### Experiment 3（5 场景）

| arm | claimCorrectness | citationCorrectness | completeness | humanPreference |
|---|---|---|---|---|
| plain-llm | 0% | 40.0% | 24.0% | null |
| paperteam | 60.0% | **100%** | **100%** | null |

paperteam 逐场景：w1/w2/w4（带语料）claim=100%、cite=100%、complete=100%、
verified evidence 1 条、gao2023survey evidence-backed；w3/w5（无语料）
claim=0%——按 M6.6 口径 legacy unverified 不构成正式证据，**如实计 0
而不是放宽口径**（这正是指标信度所在）。plain 臂：引用 40%（5 场景中
2 个捏造 key 场景 + 2 个半捏造）、完整性 24%（无管线 stage、章节 /
论断 / 引用大面积缺失）、claim 可追溯性结构性为 0。

**结论 3**：管线保障维度的差距是结构性的——可追溯性（0%→60%，上限受
语料有无约束）、反捏造（40%→100%）、完整度（24%→100%）；60% 与 100%
的差是诚实口径的代价（无语料场景没有 verified evidence 可追溯），
不是机制缺陷。

## 9. Limitations（如实，报告 JSON 内同口径随行）

1. **scripted ≠ 真实模型**：三实验度量的是确定性安全机制对注入故障的
   拦截率与管线保障（traceability / 反捏造 / 完整度），不是真实模型
   生成错误率与产出质量。0% 错误率的准确读法是「设计目标内的注入类
   全部拦截」，不是「系统无错误」。
2. **故障形态覆盖有限**：注入三类来自 scriptedRuntime 固定形态，是
   Gate / Validation 的设计目标类；真实 Writer 的错误形态更广（改写语义
   但数字不变、删段落、重排论证等未覆盖）。
3. **rag 臂是建模 + 实测混合**：「检索命中即消除捏造引文」是 RAG 生成
   条件化的建模；检索命中本身由真实 RetrievalService 实测（跨语言 claim
   无词重叠不命中——M6.4 Known Limitation，如实计入）。
4. **metadata 权威记录与 judge 是数据集内置替身**：不是真实
   Crossref/OpenAlex 与真实模型 judge；真实 judge 的漏判 / 误判率未测。
5. **baseline 臂的无信号是建模事实**（无安全机制可给信号），其 100%
   falseAcceptance 表达「直通架构在数学上不拦截」，不是测量值。
6. **Exp2 存活率依赖 HITL 策略**：默认 reject 下违规不进终稿；用户
   approve 可知情放行（留痕）——这是设计行为（用户最终控制），不是缺陷。
7. **humanPreference = null**：无人工校准记录；偏好结论需 live run +
   人工标注（接口已预留并有测试覆盖）。

## 10. Paper Contribution Mapping（论文主张 → 证据锚点）

| 论文主张 | 证据 | 强度 |
|---|---|---|
| 候选-转正分离 + 三段核验把「检索到的文本」升级为「可信证据」 | Exp1：fabricated 25%→0（quote 逐字 + metadata 各拦其类）、unsupported 17.9%→0（语义 judge）、coverage 100% 无损 | 确定性机制 + 注入实验（scripted）；强（对注入类） |
| RAG 单独不足：引文条件化消除捏造，但论断支撑无保障 | Exp1 rag 臂：fabricated 降 7.1% 而 unsupported 持平 17.9% | 建模 + 实测混合；中（需真实模型复验） |
| Revision ≠ Correct Revision：写入后复核 + 条目生命周期阻断事实漂移 | Exp2：三类存活率 / 零信号放行 100%→0、干净零误拦；拦截点前移至 revision.validate（gate 后备） | 确定性机制 + 注入实验（scripted）；强（对注入类） |
| 少量角色 Agent + 强 Tool + Evidence Layer + Quality Gate 的分层架构可提供结构性可靠性保障 | Exp3：traceability 0→60%、反捏造 40→100%、完整度 24→100%（无语料场景诚实计 0） | 管线保障口径；中强（质量维度需 live） |
| 评估可重复、指标可信度可人工校准 | 确定性离线框架 + 校准接口（agreement rate） | 工程贡献 |

写论文时的诚实约束：所有「→0%」必须限定「对注入的故障类」；
「scripted 离线」必须在方法节声明；rag 臂结论需真实模型复验后才能升格。

## 11. 后续计划

1. **Live run（首要）**：真实模型（per-Agent 配置）跑三实验同数据集，
   校准记录积累后给出 agreement rate 与 humanPreference——把「机制有效」
   升格为「端到端有效」。成本预算与采样稳定性方案先写 ADR。
2. **故障形态扩展**：真实 Writer 错误语料（M5.6 pair-02 盲评发现的问题
   类）逐步入集，度量 Gate 家族对设计目标类之外的召回。
3. **Exp3 生成质量维度**：引入独立模型盲评（M5.6 Independent Model
   Pairwise 口径）对接 humanPreference。
4. **CI 接入（可选）**：`npm run evaluation` 作为 nightly（scripted 全量
   <1min）钉住评估框架自身不回归。
5. **评估结果不反向进产品决策路径**（D-0040 边界维持）；若未来 Gate
   阈值调整需要实验依据，走独立 ADR 引用 reports/ 产物。
