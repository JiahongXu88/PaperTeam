# M10.4.3 — Fact Preserve Plan Deduplication：Harness 修复与模型路由重验证

日期：2026-10-02　判定：**完成（缺陷修复 + 回归全绿 + A1/A2 真机重跑；harness 确定性死亡模式消除、两臂均走完守卫裁决路径；模型结论维持 all-strong 默认，A2 单样本合格信号如实登记但不足以翻案）**

---

## 1. Problem

M10.4.2 基准 7 次真实运行中 2 次（A1·attempt-2 strong / A2·attempt-1 flash）死于同一 tier 无关故障：

> Writer 在 ≥2 处做**内容完全相同**的未授权事实修改 → fact checker 如实产出多条同 `violationKey` 违规 → `revisionPlan.ts` 把 `fact-preserve:<violationKey>` 直接当条目 id（无去重）→ M9.10 构建期断言 `duplicate_item_id` 抛错 → `revision.plan` stage 失败 → **整个 revision run 在 repair 派生点确定性死亡**。

该缺陷把「本可在 repair 循环内恢复的违规」变成了「run 级死亡」，直接污染模型路由实验的结局变量（两臂各损失一次样本）。

## 2. Root Cause

（完整分析见 `M10.4.3_FACT_PLAN_DEDUP_ANALYSIS.md`；此处摘要。）

- `cumulativeViolationKey` = sha256(`file|reason|before|after`)[0:16]（`cumulativeFactPreservation.ts:180`）是**内容指纹**——有意设计，用于跨轮 carry-forward 跟踪（key 寻址的 resolved/historical 集合语义），同一内容漂移出现 N 次产生 N 条同 key finding 是 gate 的**正确行为**。
- 真实触发形态（M10.4.2 存量产物实证）：
  - A1·2：`\includegraphics[width=0.75\linewidth]{figs/fig_pr_bdd100k.pdf}` 同行内容在稿内 ≥2 处被同时删除 → 两条 `prose_number` finding 四元组逐字节相同（key `49742c0c9bd329e8` ×2）；
  - A2·1：同一新增行内多个新数值 token 各产生一条 `added_number` finding，`after` 同为该行快照（key `d56951de40b0b6c0` ×2）。
- `buildRevisionPlan` 的 fact-preserve **主路径**（M10.3.1 引入）直接拼 key 无消歧；**fallback 路径**反而有 `findingCount` 计数去重——主路径恰恰是 existing-paper 工作流必经路径。
- 与 M9.7.6 `sectionMatches` 多目标重复 id（commit `14cdcf2`）完全同构：**确定性派生器按 finding×目标/出现次数扇出，而 id 只按 finding 内容寻址**。两案的下游 fail-closed 断言（M9.7.6 转移协议 / M9.10 schema）都是正确行为——同 id 双条目会让状态机 byId 匹配与 `revision_items_resolved` 计数不可信，坏计划静默落盘比阻断一次 run 严重得多。**断言一行未动。**

## 3. Fix Design

**修复层选择**：不改 violationKey 公式（会断跨轮跟踪）、不在 gate 侧折叠 finding（gate 必须如实报告出现次数）、不在 `buildCumulativeFactRegressions` 合并（丢出现信息）——只在 `buildRevisionPlan` 的 id 派生层加确定性出现序号：

```
fact-preserve:<violationKey>:<N>   N = 同 key 在输入中的第 N 次出现（0 基，按输入顺序计数）
```

- 纯函数计数（`nextOccurrence`），无随机 / 时间源，同输入同输出；violationKey 为 16 位 hex 不含冒号，id 文法无歧义；fallback 路径（`fact-preserve:<file>:<n>`）原样保留。
- 同 key 的 N 条违规各得一条目，**全部违规信息逐条保留，无覆盖**。
- 唯一 id 格式消费者 `definitions.ts` restore 回写同步适配：`id.slice("fact-preserve:".length).split(":")[0]` 反解 key，兼容新旧格式与 fallback。同 key 全部出现随 key 恢复一并闭环；未真恢复的出现由下一轮 gate 基于快照重算暴露——计划状态不是授权来源（无洗白路径）。
- **红线核对**：Fact Gate / Quality Gate / Evidence / Revision Loop 核心语义文件零改动；改动仅 `revisionPlan.ts`（id 派生 + 注释）、`definitions.ts`（回写解析 3 行）、测试。

### 5.1 A1 是否从 deterministic failure 恢复 —— 是（就缺陷本身）

- `revision.plan` 顺利通过并产出**新格式** fact-preserve 条目（`fact-preserve:7d19d39916891d38:0`，r2 计划，随后经 revision validation 转 needs_review）——修复点直接验证 ✅。
- Run 从「repair 派生点死亡」变为**走完 3 轮 review + 2 轮修订**（r2 发现 1 条 added_number 违规 → 派发恢复 → r3 复核 → 预算耗尽 overflow → build.draft），终态死于 **pairwise fact 守卫**（rev 2→3 存在未授权改写，Draft 终态被阻断；xelatex 编译本身成功，30 页 rev-3 修订稿 PDF 产出）。

### 5.2 A2 是否仍然没有收益 —— 本样本出现合格信号，但归因须谨慎

- A2·3 是 A2 配置**首次走到 completed(Draft)**：累计事实违规 0（r2/r3 cumulative 全通过）、引用保持 ✅、修订引入 unsupported 4（vs A1·3 的 5）、build gate 通过、29 页修订稿 PDF + revision report 产出。仅剩 4 条**作者级** gate 规则（与 M10.4.0 完成基线的失败形态同类）。
- 性能：$1.67（vs A1·3 $2.74，−39%）；wall 3,257s（**快于** A1·3 3,736s）——M10.4.2 观察到的「flash writer 时延反超」在本样本未复现。
- **归因边界（如实登记）**：本 run flash writer 的 `revision.revise` 轮是 **no-op**（revisedSections:0 / changed:false，最终稿 = rev-2 的 improvement-plan 应用产物）——A2 的速度与成本优势有相当部分来自「少写 / 不写」，而非「写得同样好但更快」。M10.4.2 的机制级发现（flash 承担整文件重写时稳定需要 2 段长生成、首段 ≈1.4× strong 总时延）没有被本样本反驳，只是本次 revise 没有触发整文件重写。
- 单样本 + 已知高方差（M10.4.2 §5.6：all-strong wall 2,468–3,316s、结局 completed/failed 并存）：本样本不构成对「flash writer 无收益」结论的推翻，也不构成「flash writer 更好」的证据。

### 5.4 去重路径的真机触发情况（如实说明）

本次重跑的 A1/A2 各轮 gate 均未出现重复 violationKey（A1 r2/r3 各 1 条、A2 全 0——Writer 漂移形态是随机的，M10.4.2 为 2/7 触发率）。因此「同 key 多出现」的去重分支**由 Case B 单测 + M10.4.2 存量失败产物**证明，本轮真机只验证了「新 id 格式全程流转无回归」（派发 / restore 回写解析 / validation / 落盘读回）。这是如实边界，不是缺口：触发是随机的，修复是确定性的。

## 6. Impact on Model Routing Conclusion

**结论不变化：生产默认维持 all-strong。** 理由：

1. **样本量**：修复后每臂 n=1；M10.4.2 已确立单 run 方差显著（同配置结局 completed/failed 并存），任何单样本方向性信号都不足以改判。
2. **A2·3 的优势归因含「少写」**：flash writer 本轮 revise no-op，速度 / 成本 / 零漂移三者都部分来自「没有执行修订」而非「同等产出更便宜」。M10.4.2 的机制级负发现（整文件重写时延结构、结构化输出契约可靠性）未被反驳。
3. **A1·3 的失败是守卫正确拦截模型行为**（rev 2→3 未授权改写），不是路由可以修复的类别——换 flash 也过不了同一守卫（M10.4.2 A2·2 已示范）。
4. **修复的真实影响是实验基建级的**：tier 无关的确定性死亡模式消除后，模型路由实验的结局变量回到「模型行为 × 守卫裁决」，后续重跑不再被 harness 缺陷污染样本。

**登记的后续信号**（不改结论，供下轮路由实验复核）：修复后首个 A2 样本首次 completed(Draft) 且累计违规 0、成本 −39%、无时延反照——若后续多样本重跑中 flash writer 持续呈现「少漂移 + 少写」倾向，值得针对「no-op 率」单独立项度量（no-op 是质量优势还是消极逃避，是路由决策的真正未知数）。
