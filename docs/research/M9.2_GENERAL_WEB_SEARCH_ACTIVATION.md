## 1. 为什么在 FullText Activation 之前插入 M9.2

M8 真实验收（[M8_DEEP_RESEARCH_VALIDATION_REPORT.md]
(M8_DEEP_RESEARCH_VALIDATION_REPORT.md)）证明：Academic Search（OpenAlex /
Semantic Scholar / arXiv / AMiner）真实可用，但验收部署未配置 SearXNG——
计划中唯一一条 `kind=web` query（q-15）如实 failed，「商业 Deep Research
系统」这个一级问题域整域零覆盖（验收 §4-4 / P1-2）。

原因不是代码缺陷，是**部署配置从未真实落地**：SearXNG provider（M6.3）、
compose research profile（M5.5）、配置键 `PAPERTEAM_SEARXNG_URL` 全部已存在，
但没有任何环境真正把三者连起来跑通过。若直接做 FullText Activation，
M9.6 Full Paper E2E 验收时「研究商业产品 / 官方文档 / 行业现状」类主题
仍会缺一条腿——学术源天生覆盖不了 AI 产品、公司官网、开发者文档、
产品发布信息这类 Web 独有语料。

因此 M9.2 只做**部署激活 + 可见性 + 实测验收**，不重新设计 Search
Architecture、不新增任何商业 Search API Provider。

## 3. SearXNG 部署激活（Docker）

不创建第二套 compose——修复 / 补齐既有实现，仅一处接线改动：

```yaml
# compose.yml backend.environment（M9.2 新增，显式透传）
PAPERTEAM_SEARXNG_URL: ${PAPERTEAM_SEARXNG_URL:-}
```

设计要点：

- **显式优于隐式**：此前 backend 只经 `env_file: .env` 隐式获得该变量；
  现显式列入 environment，插值来源（shell env / compose 同目录 `.env`）
  与 env_file 双通道一致，文档单点可查。
- **缺省空串 = 未配置**：config.ts 的 `readOptionalValue` 把空串归一为
  undefined → SearXNG 不注册 → `GET /api/research/providers` 的 web 数组为空
  （前端显示「未配置」而非「不可达」，语义不撒谎）。
- **禁止 localhost 写死**：容器内地址是 service name `http://searxng:8080`
  （docker network 内部 DNS）；不设置默认值正是因为未启用 research profile
  时必须保持「未配置」状态。
- 启用方式不变：`docker compose --profile research up -d` +
  `.env` 设 `PAPERTEAM_SEARXNG_URL=http://searxng:8080`。

## 4. Native 配置方式

不经 compose 的本机开发：自行启动任意 SearXNG 实例（或指向远程实例），
在仓库根 `.env`（或进程环境）设：

```
PAPERTEAM_SEARXNG_URL=http://127.0.0.1:8080
```

backend 启动时自动加载 `.env` 补缺；`.env.example` 的 Search 段（M6.3 起）
已写明该键与 403（json format 未启用）排查提示，本阶段无新增配置键。
SearXNG 始终是 optional dependency：不配置时 Academic Search / 整个
Research Pipeline 照常工作（既有行为，测试钉死）。

## 5. Web Search 可见性（最小实现）

审计发现 `GET /api/research/providers` 后端已有、前端从未消费——用户在
Web 检索页签只有检索失败时才知道 SearXNG 不在。本阶段补最小可见性：

- `api/discovery.ts` 新增 `getResearchProviders()`；
  `hooks/queries.ts` 新增 `useResearchProviders()`（全局只读 query）；
- `DiscoveryPanel` 的 **Web 检索页签**下渲染一行状态：
  - 未配置 → warn 提示「Web 检索不可用：未配置 SearXNG
    （部署侧设置 PAPERTEAM_SEARXNG_URL，见 docs/DEPLOYMENT.md）。学术检索不受影响。」
  - 已配置 → 状态行「Web 检索：searxng（可用 / 降级 / 限流冷却中 / 暂不可达）」；
  - 观测查询失败 / 加载中 → 静默（fail-open：观测端点失败不代表未配置，
    不误报；检索失败本身已有结构化错误呈现）；
- 学术页签不渲染该行（Academic Search 永远不受 SearXNG 影响）。
- 不做 Settings Dashboard / Provider Management Console（任务书 §8 明确禁止）。

## 7. Web Result 数据模型与 Provenance

- 快照字段保持 M9.1 最小集：`provider / url / title / snippetPreview / score`；
- 本阶段新增 **optional audit 字段**（不破坏兼容，旧 artifact 照常读取）：
  - `engines?: string[]`——SearXNG 聚合的命中引擎（封顶 10 个）；
  - `publishedDate?: string`——引擎提供时的 ISO 日期（无则缺省，不伪造）；
- Provenance 链完整可答「这个 Web Candidate 从哪来」：
  executionHistory entry（executionId / queryId / query / kind / timestamp /
  providers 参与摘要）→ resultSnapshot 条目（provider=searxng + url +
  engines/publishedDate）→ CandidateStore.add（origin=web_search +
  provider + query）；
- **不做 Web Crawler**：不抓网页正文、不入 RAG（任务书 §10/§22）；
  URL 只作为身份键与 provenance 保留，本阶段不发起任何对结果 URL 的请求。
- Source type discriminator：复用既有 `CandidateOrigin`
  （academic_search / web_search / manual）——后续 Evidence 层区分
  Academic Literature / Web Source 时以 origin + identity 形态（DOI vs URL）
  判别，不引入可信度评分 / domain reputation（任务书 §13 明确不做）。

## 8. Search Result → Candidate（HITL 边界保持）

复用 M9.1 既有链路，本阶段只验证 Web 路径真实可用（§12 smoke 实测）：

- 快照勾选 → `POST /execution-results/save-candidates`
  （executionId + queryId + 下标）→ `saveWebSnapshotCandidates` →
  `CandidateStore.add`（identity = canonical URL）；
- 自动化红线全部维持：Web 检索执行不产生 Candidate / Literature /
  Evidence（测试钉死）；保存只产生 pending Candidate；
  Retrieved ≠ Candidate ≠ Literature ≠ Verified Evidence 不变量原样。

## 10. Live Smoke（真实 SearXNG，WSL2 + Docker Engine）

环境：本机 Windows 无 Docker Desktop；沿用 M5 验收路径——WSL2 Ubuntu +
Docker Engine 29.8.0 / Compose v5.5.1（镜像缓存自 M5，backend 经 bind
mount 最新 dist 组合运行——node_modules / Python / TeX 层与当前依赖完全
一致，backend package.json 自 M3.8 未变）。**真实 Docker compose 栈 +
真实公网 HTTP 请求。**

启动与接线验证：

```bash
cd <repo> && PAPERTEAM_SEARXNG_URL=http://searxng:8080 \
  docker compose --profile research up -d
# → paperteam-backend-1 (healthy) / paperteam-web-1 (healthy) / paperteam-searxng-1
curl -fsS http://localhost:8080/api/research/providers
# → web: [{provider: searxng, state: healthy}]；academic: openalex + semantic-scholar + arxiv
```

- **backend 容器 ↔ searxng 容器互访**：service name `http://searxng:8080`
  经 compose 默认网络解析，provider 注册即 healthy；
- **未配置对照**：`docker compose config` 缺省渲染
  `PAPERTEAM_SEARXNG_URL: ""`（= 未配置，Web Search 结构化 503，不误报）。

### 三类真实 Web 搜索（每类真实 URL / title / snippet / provider provenance）

| 类别 | Query | 真实结果摘录（provider=searxng） |
| --- | --- | --- |
| A 官方产品 | `OpenAI Deep Research` | github.com/openai、openai.smapply.org、ithome.com/tags/OpenAI（engines=[bing]） |
| B 官方文档 | `Anthropic Claude research` | **anthropic.com（官方主页）**、baike.baidu.com、zhihu.com（engines=[bing]） |
| C 通用技术 | `deep research agent architecture` | bing cn 结果（DeepL / DeepSeek 相关污染，见 §12 质量限制） |

- 单查询延迟 **0.15–0.42s**（keep_only 修复后；修复前 google cse 等默认
  引擎超时把每次查询拖到 10s+ 且恒定 degraded——见下方模板修复）；
- `status: degraded` 如实出现：baidu 引擎当日 CAPTCHA 挂起 1h
  （SearXNG 设计内行为），bing 结果照常返回——「degraded ≠ 不可用」
  语义经真实部署验证。

### 部署模板真实缺陷修复（docker/searxng/settings.yml）

live smoke 暴露：`use_default_settings: true` 不是白名单语义——上游默认
引擎（google cse 等）仍在跑，大陆网络超时 → 每次查询拖慢 +
`unresponsive_engines` 恒非空 → 恒 degraded。修复为官方 keep_only 语法：

```yaml
use_default_settings:
  engines:
    keep_only:
      - bing
      - baidu
```

重启 searxng 容器后延迟从 10s 级降至 0.15–0.42s，degraded 只在引擎真实
挂起（baidu CAPTCHA）时出现。这是本阶段唯一的 SearXNG 模板改动。

## 12. Known Limitations

1. **Windows host 无原生 Docker**：live smoke 经 WSL2 Docker Engine 完成
   （M5 同款路径）；Windows Docker Desktop 环境未单独验证（compose 文件
   平台无关，预计行为一致）。
2. **SearXNG 引擎质量取决于上游**：模板默认大陆直连引擎（cn.bing + baidu），
   baidu 偶发 CAPTCHA 时 SearXNG 自动挂起该引擎 1h（结果可能变少或
   degraded，但链路如实标注）；境外引擎需在 settings.yml 配代理。
3. **publishedDate 稀疏**：多数引擎不给日期，快照中该字段经常缺省——
   如实呈现，不伪造。
4. **Web 结果不去重于学术结果**：同一致信息（如 arXiv 页面）可能同时
   出现在 academic 与 web 结果中；CandidateStore 的身份判等（DOI vs
   canonical URL 形态不同）不合并两者——留给 Evidence 层按需处理。
5. **不做网页正文抓取**：M9.2 是 discovery，不是 crawler；FullText /
   正文 RAG 不在本阶段（M9.3 是文献库全文激活，Web 正文抓取未排期）。
