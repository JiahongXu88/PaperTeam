## 3. idea_to_paper 原断点（静态审计 + 源码核实）

- **后端完整可用**：`POST /api/projects/:id/workflows` 的 `kind` 缺省即
  `idea_to_paper`（`httpServer.ts` readWorkflowKind），run 输入完全来自项目
  元数据（researchIdea 等，创建项目时写入）；workflow 定义
  `createIdeaToPaperDefinition`（research.idea → evidence.ground →
  research.feasibility → … → build.final）与 checkpoint / 恢复语义齐备。
- **断点在 UI 调用层**：`useCreateWorkflowRun` 的全部 4 个前端调用点
  （NewProjectPage:382 / ProjectAside:167 / ReviewPanel:165 / ReviewPanel:176）
  的 kind 全部是 existing 系列——**0 个 `kind: "idea_to_paper"` 调用点**；
  IdeaForm 创建项目后只 `navigate('/projects/:id')` 不发起 run；ProjectAside
  的启动按钮被 `isExistingPaper()` gating 排除 idea 项目，且「快捷操作」区块
  本身被 `hasDoc` gating（idea 项目无 PDF，整块不渲染）。用户从浏览器建完
  idea 项目后无任何「开始写论文」按钮，run 永远不会被创建。

## 6. Search → Candidate HITL 流程

- **后端**（`backend/src/search/researchDiscoveryService.ts` 新增两个方法，
  与既有 saveAcademic/WebCandidates 汇聚同一 `CandidateStore.add` 写入口径）：
  `saveAcademicSnapshotCandidates` / `saveWebSnapshotCandidates`——identity 用
  执行时冻结的归一化身份（学术快照完整保留；web 经 buildIdentity 重建），
  元数据只能来自快照投影，调用方无法按值伪造。
- **HTTP**（`httpServer.ts` research 分支）：`POST /api/projects/:id/research/
  execution-results/save-candidates`，body `{executionId, queryId,
  saveAsCandidates: number[]}`（快照下标）；200 `{saved, mergedExisting}`。
  项目 scoped + execution/query scoped + 结构化错误：
  - 404 `EXECUTION_ENTRY_NOT_FOUND`（executionId + queryId 定位不到）；
  - 409 `EXECUTION_RESULTS_UNAVAILABLE`（条目 failed，或 M8.5 及更早形态
    无快照——引导用 Discovery 检索面板重新检索后保存）；
  - 400 `INVALID_REQUEST`（缺字段 / 空数组 / 越界下标）。
- **前端**（DiscoveryPanel 执行审计区内嵌 `ExecutionSnapshotPicker`）：
  每条 executed 条目若有快照 → 渲染勾选列表（provider / 年份 / DOI / arXiv /
  预览 chips，与检索结果行同视觉）→「保存选中（N）为候选」→ 成功反馈
  （含 mergedExisting 合并说明）+ 失败反馈 + 勾选清空；候选保存后经既有
  候选审阅区（accept / reject / promote）继续。
- **Research Loop 关系零改动**：Loop 仍只负责 Plan → Execute → Coverage →
  Gap → Iteration，不自动保存候选；`researchLoop.ts` 状态机零改动。
- **API 复用**：读取走既有 `GET /research/execution-history`（新字段自动
  带出）；保存是新端点（唯一新增，围绕「读 snapshot / 存 candidate」）；
  不创建第二套 Search API。

## 10. Known Limitations

1. **快照是投影不是全文**：abstract 只留 ≤300 字符预览；保存候选后
   CandidateSource.snippetOrAbstract 继承预览（完整摘要经既有 enrich /
   promote 链路补全）。
2. **M8.5 及更早执行条目无快照**：保存引导走「重新检索」（检索缓存 TTL
   10min 的约束仍在——这是有意设计，不在本阶段放开）。
3. **web query 快照身份重建**：web 快照经 buildIdentity({url,title}) 重建
   身份（与 saveWebCandidates 同构），provider 返回的 URL 变化会产生新身份
   （canonical 化规则同既有链路）。
4. **idea run 的产物质量不在本阶段验收范围**：M9.1 只接通「入口 + 衔接」；
   evidence.ground 在纯检索场景仍可能 no-op（M8 验收 §4-3 的事实），锚定
   证据调研流是 M9.2+ 任务。
5. **快照不回填 resultIdentifiers**：两者并存（identifiers 全量 ≤50 字符
   投影、snapshot Top-10 结构化投影），UI 悬停标识 + 勾选快照各司其职。
