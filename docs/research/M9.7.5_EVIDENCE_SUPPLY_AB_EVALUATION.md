## 1. Goal

M9.7.3 结论：Verified Evidence 只覆盖 3 篇种子，而 bibliography 20~36 keys，
Evidence Coverage ≈ 3/N；Writer Prompt 无法突破上游 Evidence Pool 的结构性
天花板。本阶段通过受控 A/B 验证：**主动扩充 Evidence Supply（Candidate HITL
→ Promote → FullText → 重跑 research → grounding）是否真实提升
evidence-backed citation coverage、unsupported claims、review convergence
与整体可靠性**。

- H1：扩大 Verified Evidence Source Pool → Evidence Coverage ↑
- H2：Evidence Pool ↑ → Unsupported Claims ↓？
- H3：Evidence Pool ↑ → Review/Revision 更易收敛？
- H4：收益是否值得 FullText / Grounding / Token / 时间成本？

## 13. Failure Cases（重大失败与 Root Cause）

1. **`revision.revise`：`revision item transitions 包含重复 id`（产品 bug，
   阻断性）**——A 两次 run 共两次触发（r1 与 r3，均 transient 2/2 重试
   耗尽 → workflow.failed）。根因：Writer revision 输出的 transitions 对
   同一 plan item 产生重复 id，`applyRevisionItemTransitions`
   （`backend/src/review/revisionItemStatus.ts:95`）纯函数校验拒绝重复，
   不做部分应用（设计如此，状态损坏应当暴露）。修复方向：revise 调用方
   对 transitions 按 id 去重合并（同 id 取后到状态）或让 Writer 输出契约
   显式禁止重复。**这是本实验 Arm A 无法产出 PDF 的唯一原因，与 Evidence
   Supply 变量无关**（B 同一阶段正常通过）。
2. **A2 `research.idea` timeout（900s 无进展）**：第 1 次尝试超时，第 2 次
   自动重试成功。环境因素（semantic-scholar/openalex 密集 429 限流冷却），
   stage 内建 maxAttempts=2 兜底有效。
3. **S008/S011 fulltext 不可得**：DOI-only 期刊文献（无 arxivId）在 resolver
   失败后无合法 manual 路径（产品无 DOI 付费墙外下载能力，实验不绕过）——
   funnel 8→6 的损耗全部来自此类。属产品能力边界而非 bug。
4. **S007 CRITIC「有全文无证据」**：automatic fulltext 成功、171 chunks 入
   索引，但 researcher 重跑未对其提出证据候选 → 0 verified records。
   Researcher 的 chunk 检索选择是漏斗的真实环节（非确定性）。
5. **运维事故（如实记录）**：实验初期 backend 环境变量误配（`PORT` 应为
   `PAPERTEAM_PORT`、projects root 变量为 `PROJECTS_ROOT` 无前缀）导致
   一次 pre-treatment 跑进默认 `backend/projects`；清理时误用通配符
   `rm -rf backend/projects/p-*` 删除了 5 个**非本轮创建**的历史遗留项目
   目录（gitignored 实验副产品，非正式数据，不可恢复）。违反"只删本轮
   创建白名单"纪律，引以为戒；对本次实验数据无影响（正确命名空间下的
   数据完好）。

## 14. Interpretation（对照预注册的五种情况）

**情况 B：Evidence Source ↑（3→8）、Coverage ↑（11.5%→44.4%）、
Unsupported 不降反相对劣化（r2 后 9/40=22.5% vs A 2/26=7.7%）——
Citation grounding 显著改善，Claim grounding 未同步改善。**

- H1 **SUPPORTED**：coverage 3.9 倍提升，机制是 source 数而非引用次数；
  utilization 100%（新增 5/5 全部被消费）证明 M9.7.2 的 evidence-backed
  writer 在供给充足时兑现结构性收益，M9.7.3 的天花板确实在 supply 侧。
- H2 **NOT SUPPORTED**：更大证据池让 Writer 写出更多有支撑的事实性论断
  （SUPPORTED 24→28），但 reviewer 判定的 unsupported 池没有缩小——证据
  供给只解决"引用有据"，不解决"每个 claim 有据"（claim 级 grounding 是
  writer 证据选择 + reviewer 判据的独立问题）。
- H3 **NOT SUPPORTED**：B 一轮 REGRESSION 后 stalled；A（证据更少但更弱
  化的稿子）连续 IMPROVED。证据更多不等于更容易收敛。
- H4 **支持（exploratory）**：每新增 verified source ≈$0.1、每 10pp

## 附：十问回答（实验设计 §23）

1. **扩 Evidence Pool 是否真正提高 Evidence Coverage？** 是。11.5% → 44.4%
   （3/26 → 8/18），同 fork 起点、同模型、同策略。
