## 1. 问题（M17.2 遗留 D5 / D6）

M17.2 已经能把实验数值写对（真实稿件 45/45），但方法节的两类事实没有任何权威来源：

- **D5**：修订阶段新写入一个方法参数，取值是作者给定值的 100 倍（作者写的是比例值，稿件写成了百分数标度）。
  还原事件链后发现：这个值**最早由审稿意见从配置名推断出来**，修订照做，第二轮审稿又把它当作「已采纳」。
  已有的事实守卫只保护「已有数字被改动 / 删除」，新增数字是盲区；模型自称「已核验」被当作通过。
- **D6**：作者明确说明某组件 G 已从当前方法中去掉；研究想法分析的「研究空白」把 G 列为超参数，大纲随之把 G 写成当前组件，
  Writer 照大纲扩写了 G 的作用机制。审稿与守卫都没有发现。
- 共同根因：大纲、写作与修订阶段**从不读取作者的研究想法原文**，只读取研究员的二次概括；系统里不存在「参数取值」与「组件状态」这类可核对的事实。

## 2. 设计：作者确认的方法事实（method-facts/v1）

不新建平行的证据库或运行时，挂在已有的实验数据包 / 写作上下文单点上：

| 要素 | 内容 |
|---|---|
| 参数事实 | 符号 + 别名（LaTeX、中文名称）+ 取值 + 标度 + 适用配置 + 来源定位 |
| 组件事实 | 名称 + 别名 + 状态 `ACTIVE / REMOVED / PROPOSED / UNKNOWN` + 适用配置 + 来源定位 |
| 权威性 | 只有作者在产品中确认的版本（`mfs-NNNN`，带内容哈希，旧版本不可变）才是权威；研究想法原文的确定性抽取只是**候选**，不约束任何判定 |
| 失效 | 作者撤销，或确认后修改研究想法原文 → 状态 stale / revoked，立即不再支撑任何论断，不悄悄沿用旧事实 |
| 与实验快照 | 可关联但不混同：方法参数不是实验指标；快照指标名上的赋值仍归实验数值核查 |

接入路径（同一份上下文）：研究想法分析 → 大纲 → 分节写作 → 修订，都收到「作者确认的方法事实」块
（候选与失效状态分别有明确文案；配置名 / 变量名中的数字不是参数取值；与审稿意见冲突以事实为准）。

确定性核查（零模型，不依赖 Writer / 模型自证）：

1. **大纲**：生成后立即核查，记录责任阶段（`reviews/method-fact-audit-outline.json`），冲突出现在大纲确认请求中，
   并作为「大纲纠偏」注入每一节写作，正文不得照错误大纲扩写。
2. **初稿**：写作完成后再核查一次（`-writing.json`），区分「大纲带入」与「写作新增」；不自动重写（不追加模型调用）。
3. **审稿**（每轮独立）：与已确认事实冲突 → fact **major**（质量门禁计入，门禁阈值未改动）；
   无来源的参数取值、无法判断主体的组件提及 → minor 且标记需作者裁决；没有有效事实表时不报「方法事实保护通过」（`evaluated=false`）。
4. **修订补丁守卫**：候选补丁若**新引入**参数冲突、把已移除组件写回当前方法，或新增没有作者来源的参数取值，则拒绝并进入既有的有界修复通道。
   补丁前已存在、未被加重的问题不归咎于该补丁，由审稿继续报告。

判定规则要点：

- 数字绑定的是「主体 + 数值 + 标度 + 配置」：同一个数字出现在别处不构成来源。例如参数 A 的值写到参数 B 上，判冲突。
- 归一化：小数位、科学计数法（`3.5e-1`、`3.5\times10^{-1}`）、`%`、符号、显示精度舍入容差都按等价处理；`50` 永远不等于 `0.5`，冲突详情会提示「疑似 ×100 标度错误」。
- 结构性数字（`\ref` / `\label` / `\cite`、下标 `\sum_{i=1}`、章节 / 表号、数据集名中的数字）不进入参数核查。并列句「a 与 b 分别为 x 与 y」不做位置归属（宁可漏报，不误绑）。
- 组件提及分类：否定（去掉 / 不使用 / without）、历史（旧版曾使用）、他人工作（引用且无自指）、拟议（未来工作）、不确定，其余视为「断言当前方法」。
  相关工作节中无自指的提及记为不确定，交作者裁决。
- 已知边界：多字母词（如 IoU）只有登记为别名后才按参数核查；未加符号的自然语言参数描述只覆盖已登记的中文名称；规则无法判断的语义记 UNCERTAIN，不臆造来源。

作者入口：「实验数据」页的「研究方法事实（作者确认）」区。候选从研究想法原文预填并标注未确认，作者逐条核对、修改、补充别名与适用配置后确认；也可填写原因撤销。
HTTP 接口：`GET/PUT /api/projects/:id/experiment-packages/method-facts`，`POST …/method-facts/revoke`（见 API_CONTRACT）。
