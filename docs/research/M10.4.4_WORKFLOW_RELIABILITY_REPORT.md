## 1. Problem

两个已有真实证据的可靠性问题：

- **A. Finding Dispatch**：Reviewer 已发现的问题可能永远送不到 Writer。Reviewer 输出契约允许 section 用「章节名」（`ReviewerService.ts:559`：`"section": "sections/xxx.tex、abstract（摘要问题归这里）或章节名"`），但派发侧 `sectionMatches` 只认路径 / stem / key——单文件 main.tex 项目（M10.3 真实返修场景）heading 式引用从不命中，finding 被计划记录（planned）后永久滞留（M10.4.1 A3；M10.4.2 A1 真实产物回放：r2 29 条 issue 仅 6 条命中，且全部是「引用里恰好含 main 字样」的偶然命中）。
- **B. Provider Stall**：Provider 请求可能长时间零响应导致白等。M10.4.1 plan.improvement 第 1 次尝试实测：请求发出后 ~900s 无任何 model turn 输出（0-turn），最终由 stage 无进展 deadline（`DEFAULT_STAGE_TIMEOUT_MS`=900s）abort；Pi 自身 auto-retry 需要错误事件触发，0-activity 挂起不触发任何既有重试——长任务执行预算 30min 内 Runtime 层无静默期防线。

## 2. Finding Dispatch Root Cause

（完整分析见 `M10.4.4_DISPATCH_STALL_ANALYSIS.md` 第一部分。）

三层脱节：

1. **契约与实现脱节**：prompt 允许「章节名」；单文件 digest 的块标签就是 `main.tex · <标题>`（`splitSingleFileDigest`，M10.3）——系统引导模型用 heading 指位，matcher 却不读标题。
2. **单文件项目的三重漏派发**：唯一目标 `{key:"main.tex"}`（stem="main"）下，(a) heading 引用（`方法/3.6 轨迹稳定性自适应损失`）8 个路径谓词全 false；(b) 摘要类引用被 `isAbstractSectionRef` 早退 false——单文件项目没有独立摘要目标，摘要物理上就在 main.tex 里；(c) 命中的全是 `ref.includes(stem)` 偶然吸收（`tab:main_*` 等）。
3. **结构信息缺失**：修订链路不存在任何持久化 heading 结构（导入零解析、outline 只存在于写作流、`splitSingleFileDigest` 即席正则且不支持嵌套花括号——真实论文 `\subsection{…MRG\mbox{-}\nDTM…}` 跨行标题会截断）。

## 3. Finding Dispatch Fix

`sectionMatches` 分层匹配（全部确定性，零 NLP）：

```
0. 哨兵引用（(global)/(unknown)/空）不匹配
1. 摘要互斥（M4.8）+ grounded 补充：摘要类引用对普通目标仅当该目标
   自身内容含摘要环境才匹配（单文件 main.tex 恢复派发；outline 组装根
   不入目标、章节文件无摘要环境 → 行为不变）
2. 路径 / stem / key 匹配：既有语义逐字保留
3. heading 匹配（grounded in target.currentLatex）：
   平衡花括号提取 \section 系标题（支持嵌套 \mbox 与跨行）→ 双侧归一化
   （\mbox 展开 / 命令删除 / 连接号统一 / 去空白 / 小写）→ 引用切段
   （分隔符 / 括号注释 / 前导编号剥离）→ 先「段 == 标题」精确匹配
   （文档序），后「标题 ⊆ 引用」子串兜底（≥2 字）
4. ambiguous：同一标题物理存在于多个目标 → 全部 grounded 目标派发
   （M9.7.6 同 id 合并防重复；findingDispatch.multiTarget 显式计数）
5. 无法可靠匹配 → unmatched 诚实滞留（不广播、不伪造）
```

配套：`itemTouchesFile`（revisionValidation 归因）可选 contents 启用 grounded heading 归因——heading 条目被派发应用后其违规归因不再漏看该文件（outline 组装根只含 `\input` 无 `\section`，天然不误归因）；`revision.revise/apply` stage 结果新增 `findingDispatch{total,matched,unmatched,multiTarget}` 派发覆盖诊断。

**故意不做**：编号→标题映射（真实产物中 reviewer 编号与 LaTeX 实际编号错位——A1 r2 用 3.6/3.7 指方法节小节，按编号派发有错派风险；编号+标题并存引用由标题段命中）；全 finding 广播（M10.4.1 已否定的上下文膨胀）。

## 4. Provider Stall Root Cause

卡点层级：`session.prompt` → pi-agent-core `streamAssistantResponse` → `streamFunction`（provider HTTP 流）。**provider 首个流事件（`case "start"`）到达时才发出 assistant `message_start`**——即「provider 活着」的第一信号。挂起 = 该事件永不到来 = 无错误事件 = Pi auto-retry 不触发 = 只能等 stage deadline（900s）/ execution 预算（长任务 30min）。provider 内部原因不可观测，本报告只声明「provider request 长时间无 activity」。

关键语义区分（pi-agent-core 源码确认）：user prompt 回声 `message_start/end`（role=user）、`agent_start/turn_start`、`tool_execution_*` 都是**本地事件**；只有 assistant 消息事件（message_start/update/end，role=assistant）是 **provider 活动**——thinking/reasoning delta 亦为有效活动（先于正文 token）。

## 5. Watchdog Design

**First-Activity Watchdog**：`runOnSession` 武装 execution timer 的同时武装 first-activity timer；事件转发器观测到首条 assistant 消息事件即解除。

| 维度 | overall timeout（execution） | first-activity timeout（新增） |
|---|---|---|
| 约束区间 | 整个执行段（含全部合法长生成） | 仅「首条 provider 活动之前」的静默期 |
| 保护对象 | 任务不无限运行 | 不为 0-activity 挂起白等 15~30 分钟 |
| 误杀风险 | 长生成须留足预算（长任务 30min） | 首活动到达即解除，与生成长度无关 |

机制约束逐条落实：first-wins `abortInitiator`（cancel 优先于 watchdog，E 用例）；与 execution 超时共用 abort / self-healing rotation / `AgentTimeoutError(phase="first_activity")` / 既有 stage retry（category timeout）通道，**不新增第二套重试**；`timed_out(FIRST_ACTIVITY_TIMEOUT)` 结构化终态可回溯（getTask）；trace 记 `task.firstActivityMs`、`model.turn` 属性 `model.ttfbMs`、`first_activity_timeout` 事件（threshold/elapsed）——不伪装成普通 provider error；timer 在首活动 / prompt 结束 / settle / close 全路径清理并 unref。

**默认值 180,000ms（3 分钟）**：不是拍脑袋——按任务纪律先落 instrumentation（`model.ttfbMs` / `task.firstActivityMs`），真实 E2E 采集分布（§7）回填验证：**74 次真实 provider 请求 TTFB min=158ms / p50=3.4s / p95=7.9s / max=8.4s → 180s 对实测最大值有 21× 裕量**。`PAPERTEAM_PI_FIRST_ACTIVITY_TIMEOUT_MS` 可配，0=关闭。

**边界（如实）**：watchdog 只覆盖本 run 首个 provider 请求的挂起；agent loop 中途（首活动之后）下一轮请求挂起仍由 overall execution 超时兜底——per-turn watchdog 会改变长生成超时语义，超出本里程碑边界。

## 9. Remaining Limitations

- 无法控制 provider 服务端行为：watchdog 只能把 0-activity 故障的等待从 15~30 分钟压缩到 ≤3 分钟并交既有重试，不能消除故障本身；本轮真实 E2E 未自然复现 hang（正常，不为此烧钱复跑）。
- watchdog 只覆盖 run 首个 provider 请求；中途轮次挂起仍由 overall execution 超时兜底。
- ambiguous section（同一标题在多个目标文件）按 grounded 全目标派发（multiTarget 显式计数），不静默任选；真正的错派风险在于引用本身语义含混，最终由复审 / HITL 兜底。
- 子串兜底层对「标题恰好是引用中普通词」存在理论误派可能（如 2 字标题「方法」出现在话题式引用里）；精确段匹配优先 + grounded 约束 + 本轮真机 0 错派，残余风险登记不扩权。
- §7.1 两项（Writer 图名翻译破坏编译；accept_draft 路径无 repair_latex）为后续工程跟进候选。
