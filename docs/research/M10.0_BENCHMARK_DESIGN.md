## 1. 研究问题与假设（预注册）

| # | 研究问题 | 可检验假设 | 判定指标（详见 METRICS） |
| --- | --- | --- | --- |
| RQ1 | 在深度调研任务上，分层证据管线是否产出更可靠的文献覆盖与来源质量？ | H1：Arm P 的引用存在正确率与学术覆盖（gold）≥ Arm C，且来源精度不劣于 | C1 citation existence、A3 coverage、A2 precision |
| RQ2 | 在论文生成任务上，证据接地是否降低无支撑论断与捏造引用？ | H2：Arm P 的 unsupported claim rate 与 fabricated citation rate 显著低于 Arm C/L，且差距不能仅由「写得更少」解释（按可检验论断密度归一） | B1 grounding rate、B2 unsupported rate、C2 fabricated key rate |
| RQ3 | 优势的成本代价是什么？ | H3（探索性，无方向预设）：Arm P 的 token/时间/金钱成本相对 Arm C/L 的比值区间 | F1-F3 cost 族 |
| RQ4 | 独立专家盲评是否偏好 Arm P 产物？ | H4： pairwise 偏好中 P>C 的概率 >0.5（按任务配对） | H-overall、pairwise preference |

诚实约束（继承 M6.8 §10 纪律）：H2 的强弱措辞取决于 live 样本量；n 小时只声明
「方向性证据」。RQ3 不预设方向——若 PaperTeam 成本高一个量级，这本身是必须如实
报告的 trade-off 结论。

## 2. 三臂设计（对照阶梯）

设计原则：三臂共享同一底层模型与同一任务卡，**唯一系统性差异是 workflow 层**，
形成「无工具记忆生成 → 工具型通用 Agent → 证据接地管线」的归因阶梯。

| 臂 | 名称 | 形态 | 工具/检索 | 交互规则 |
| --- | --- | --- | --- | --- |
| **L** `chat-llm` | 普通 LLM（ChatGPT 类 workflow 下锚） | 同一模型多轮对话，仅任务卡 + 自己前文 | 无检索、无工具 | 允许模型自行组织多轮（「继续」「自检一轮」），固定轮次预算；模拟典型用户 chat workflow |
| **C** `coding-agent` | 通用 Coding/Research Agent（Claude Code 类） | Claude Code CLI headless（`claude -p`），同模型经 anthropic 兼容网关（P0 冒烟，见 PROTOCOL §2） | 原生工具集（WebSearch/WebFetch/文件/脚本），**不额外供学术 API** | 权限模式固定、无人工纠偏；仅在停下询问时给中性「continue」 |
| **P** `paperteam` | PaperTeam 完整 `idea_to_paper` | 产品 API 驱动（M9.7.1 协议蓝本），受控研究循环形态（全部检索走计划执行通道，对冲审计 G2） | Academic Search / Web Search / FullText / Evidence 三段核验 / 确定性书目 | HITL 脚本化默认批准（可行性确认=approve、大纲确认=approve、修订复核=按系统建议） |

**消融登记（不进主实验，防过度扩张）**：C+ 臂（coding agent + 与 PaperTeam 同源学术
API 工具）用于分解「工具集 vs 编排」混杂因子——只在主实验结论成立且争议聚焦于工具
混杂时立项，走独立 ADR。

**为什么不复用 M6.8 的 rag 臂**：M6.8 Exp1 已在机制层证明 rag 单独不足（fabricated
25%→7.1% 但 unsupported 持平 17.9%）；M10.0 的问题是系统级对照，rag 不是真实用户
workflow。

## 3. 任务卡（Task Card）——主题无关的任务抽象

### 3.1 设计要求

1. **不绑定主题**：任务卡是数据，不是代码；换主题=换卡，协议零改动。
2. **三臂同输入**：`topicBrief` + `deliverable` 逐字进入三臂 prompt/表单。
3. **同构交付物**：硬约束三臂都交付 `main.tex + sections/*.tex + references.bib`（+
   可选 PDF）。这是全部机械指标可比的前提（AUDIT §8-1）。统一 LaTeX 模板随任务卡
   下发（模板本身无系统指纹）。
4. **可验证性**：每卡带可选 `anchors`（已知关键文献 DOI/arXiv），供 gold 构建与
   seed 命中率计算；不作为运行时输入。

### 3.2 Schema v1

```jsonc
{
  "taskId": "task-<slug>",
  "schemaVersion": 1,
  "status": "draft | frozen",          // frozen 后不可改，记录 sha256
  "origin": "user_question | paperteam_self | external_survey",
  "language": "zh | en",
  "domain": "…",                        // 一级学科
  "topicBrief": "…",                    // 研究问题陈述（150-300字/词），三臂唯一主题输入
  "deliverable": {
    "type": "survey_article",           // survey_article | method_related_work | position_paper
    "targetLengthWords": [2500, 6000],
    "requiredSections": ["introduction", "…", "conclusion"],   // 结构完整性检查表
    "citationMin": 12,
    "format": "latex",                  // 统一模板随卡下发
    "templateRef": "eval/templates/neutral-v1.tex"
  },
  "budget": { "wallClockMin": 90 },     // 各臂统一硬时限
  "anchors": [ { "doi": "10.…", "why": "…" } ],   // 可选，≤8 条
  "freeze": { "frozenAt": "…", "sha256": "…" },
  "provenance": { "author": "…", "createdAt": "…", "selectionNote": "…" }
}
```

### 3.3 任务来源三类（对应项目允许的未来替换）

| origin | 定义 | 例子（示例占位，frozen 前可全换） |
| --- | --- | --- |
| `user_question` | 用户真实在研问题 | 例：某细分方法方向的进展综述（用户 2026 在研课题） |
| `paperteam_self` | PaperTeam 自身研究方向（自引用测试：系统调研「自己这类系统」） | 例：LLM Agent 工作流可靠性/评估方向综述 |
| `external_survey` | 其他领域综述任务（域偏移测试） | 例：临床医学某术式比较、环境科学某方法综述 |

### 3.4 遴选标准（任务卡入库门槛，全部满足才可 frozen）

1. **文献可核验**：主题在 OpenAlex/arXiv 有 ≥50 条可检索文献（机械核查）。
2. **边界可窄**：能在一篇 2.5k-6k 词综述内立住（不选「整个领域百年史」类宽题）。
3. **非时效敏感**：不依赖近 30 天事件（避免三臂检索窗口不同造成的混杂）。
4. **语言分层**：zh/en 至少各 2 卡（对齐 M6.8 中英场景先例）。
5. **领域分层**：至少跨 3 个一级学科（含 ≥1 非计算机领域，测域偏移）。
6. **难度分层**：成熟领域（文献密集）/ 新兴方向（文献稀疏）各半——密集区考验
   覆盖与排序，稀疏区考验不捏造（引用下限压力）。

### 3.5 首批任务集（示例，main 实验前 frozen）

Pilot 3 卡（先跑通）：1× AI 方向（paperteam_self, en）/ 1× 交叉领域（external_survey,
zh）/ 1× 用户问题（user_question）。Main 扩至 6-8 卡（每层 ≥2）。示例主题以
`example-` 前缀登记在任务集 JSON 内（M10.1 实现时物化为 `evaluation/tasks/`），
**本设计文档不锁定具体题目**——锁定发生在 freeze 环节并记 sha256。

## 4. Gold 参考文献集（coverage 分母的构建协议）

A3 学术覆盖需要每任务一份 gold 列表。构建纪律（顺序固定，防泄漏）：

1. **时机**：任务卡 frozen 之后、任何臂运行**之前**（不用「臂产出并集」做 gold，否则
   对引得多的臂有偏）。
2. **构建**：2 名构建者**独立**按 librarian 协议检索（OpenAlex 关键词 ×3 轮 + 引文
   雪球 ×1 轮 + anchors 并入），各出候选 20-40 条 → 机械去重 → 合并会议裁决
   （纳入标准：与 topicBrief 直接相关 + 可解析身份）→ 冻结 gold（目标 15-30 条/任务，
   记 sha256）。
3. **并集敏感性检查（secondary）**：报告附录补一列「三臂引用并集口径」的 coverage，
   两个口径都报，防止 gold 构建偏差主导结论。
4. **复用**：构建过程留痕（检索式 + 裁决记录）入 `evaluation/gold/<taskId>/`。

## 5. 公平性控制（变量控制总表）

| 变量 | 控制方式 | 残余混杂（如实登记） |
| --- | --- | --- |
| 模型 | 三臂同跑 GLM-5.3（PaperTeam 默认配置即它）；C 臂经 anthropic 兼容端点接同一网关（P0 冒烟） | 通道差异（网关协议翻译）不可完全消除；降级时 C 用 Claude 系模型并登记混杂 |
| 主题 | 同一 frozen 任务卡逐字输入 | — |
| 时长 | 同 `wallClockMin` 硬时限（超时取最后完整产物） | 三臂对时限的利用率不同是**测量对象的一部分**，不剔除 |
| 人工干预 | 统一「中性脚本」：P 臂 HITL 默认批准；C/L 臂仅中性 continue；全程记录每次干预 | 默认批准对 P 有利/不利方向未知——敏感性分析：P 臂另跑 reject-on-blocked 变体（子样本） |
| 采样随机性 | 无 seed 可控（审计 G10）→ rep≥2 + 随机化执行顺序 | run 间方差进误差项 |
| 网络/限流 | 同机、同网关、同出口 IP；**三臂串行执行**（M9.8 教训：并行互抢限流） | 时间日漂移；用随机化臂序 + 记录网关 request id 对冲 |
| 检索语料 | 不给任何臂私有语料；都从公网/OA 出发 | 检索栈不同是系统差异的一部分（比较的就是 workflow） |
| 产物渲染 | 三臂统一 LaTeX 模板；盲评前由评估方统一重渲染（见 HUMAN_EVAL §3） | — |

## 7. 规模与预算（概算，详见 PROTOCOL §8）

- Pilot：3 卡 × 3 臂 × 1 rep = 9 runs。按 M9.7.1 锚（P 臂 ~45min/$3.5），三臂合计
  约 7-9 机器小时、直接成本 ~$30-50（C 臂成本未知，pilot 顺带测）。
- Main：6-8 卡 × 3 臂 × 2 rep = 36-48 runs，约 40-60 机器小时、~$150-300。
- 人工：gold 构建 6-8 任务 × 2 人 × ~1h；盲评 6-8 任务 × 3 评者 × (3 篇绝对评分 +
  3 对偏好 + 抽检) ~1.5-2h/任务。
