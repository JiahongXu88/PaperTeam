## 2. Parser 选型

**选择：Docling（第一候选，实际采用）**，经本机真实安装验证（docling 2.130.0，
Python 3.11.9，清华 PyPI 镜像 + hf-mirror 模型镜像）。

- 实测 `attention.pdf`（15 页真实论文）一次转换产出 161 块：150 text /
  4 table（headers+rows+页码+bbox）/ 7 figure（bbox + PNG 资产抽取）/
  6 formula（位置登记；LaTeX 需开 enrichment）；161/161 块带页码，
  159/161 带章节标题。
- **集成成本可接受的原因**：Docling 在本项目里只是「一个更重的 pymupdf」——
  完全复用既有 `PyMuPdfParser` 的 child process 模式（execFile 无 shell、
  解释器探测、stdout 末行 JSON 协议、fd 1 重定向隔离 C 层噪声），不引入
  Python 微服务 / 常驻进程 / 消息队列 / 新数据库。未安装时显式降级（见 §7）。
- MinerU 未启用：同为 torch 系但更重（magic-pdf 全家桶），Docling 已满足
  M10.1 全部需求（版面 + 阅读顺序 + TableFormer 表格 + 图片检测），按指令
  「本轮一个生产 Adapter 足够」不做双实现。
- **已知成本**：pip 依赖大（torch 等 ~2GB）；首次解析下载布局 / TableFormer
  模型（数百 MB，落盘缓存后离线）；CPU 解析一篇 15 页论文约 40-50s。这些
  通过「后台触发 + 显式降级 + 缓存」消化，不阻塞任何主链路。

## 3. 新的数据流

```
PDF   上传 → (后台/手动) ingest → DoclingParser(child process) ─┐
                                     │ 不可用：显式降级           ├→ ParsedDocument
CSV   上传 → (内联) ingest → CsvParser(确定性 TS) ───────────────┤   (sources/parsed/<id>.document.json)
XLSX  上传 → (内联) ingest → XlsxParser(exceljs) ────────────────┘   + sources/figures/<id>/*.png

ParsedDocument ──(structured & fresh)──→ SourceChunker（docling/tabular 投影）→ 既有 chunk/RAG 管线
ParsedDocument ──(structured_record)──→ GET /records → 用户确认 → user_confirmed Evidence → 既有 Fact Preservation
```

接线完整性：后台 PDF ingest 完成（含全文自动挂载后的 ingest——先按 pymupdf
路径立即可检索，docling 完成后再按结构化产物重建）后经 `attachIngestedHook`
触发 `retrieval.rebuildSource`，docling 产物自动生效，无需等下一次库签名变化。
后台 ingest 串行执行（docling 是 CPU 密集子进程，批量挂载 12 篇时逐个跑，
不并发抢占）。

部署（一次性，机器级）：

```bash
python -m pip install docling -i https://pypi.tuna.tsinghua.edu.cn/simple
# 首次解析自动从 HuggingFace 下载布局 / TableFormer 模型；
# 国内可设 HF_ENDPOINT=https://hf-mirror.com（模型落盘后离线）
# 可选：PAPERTEAM_DOCLING_PYTHON 指定解释器
# 不装 = PDF 显式降级文本层（功能可用，表格/图/版面不可用，全部如实标注）
```

分层 seam（与 paper/PdfParser 同纪律）：

```
DocumentParser 接口（backend/src/ingestion/types.ts）
  ├─ DoclingParser        （生产 PDF adapter，child process → tools/parse_document_docling.py）
  ├─ CsvParser            （RFC4180 + 分隔符嗅探，确定性）
  ├─ XlsxParser           （exceljs 4.4.0，npm 纯 JS）
  └─ LegacyPdfTextParser  （降级链第二级：复用 paper 域 PyMuPdfParser → builtin 文本层）
```

未来换 MinerU 只替换 DoclingParser（或新增 adapter 注入），业务层 / 存储 /
Evidence / 检索层结构不变。

## 4. ParsedDocument 与 provenance 设计（M10.1A）

`backend/src/ingestion/types.ts`：

- 块类型五类：`text`（含 title/section_header/list_item/caption 细类）、
  `table`（headers + rows 网格 + 题注）、`figure`（检测 + bbox + 可选抽取
  资产 `assetName`，不做内容理解）、`formula`（LaTeX 可得时保存，否则位置
  登记）、`structured_record`（CSV/XLSX 行级记录，cells 带 header+letter）。
- `ParsedProvenance`：fileName（必有）+ page / section / sheet / row /
  column / bbox（parser 能提供就保留，绝不伪造）+ parserBlockId（docling
  self_ref，审计用）。
- **行号口径与 Excel 一致**：表头 = 行 1，首条数据 = 行 2（用户可在表格
  软件里直接对上「Sheet1 行 7 MOTA 列」）。
- 存储模型 `ParsedDocument`（schemaVersion 1）额外携带：parser、
  `parseMode`（structured / text_only）、status（ok/partial/failed）、
  counts、sheets 概览、`degradedFrom`（降级审计：从哪个 parser、因何）、
  notes（截断/告警如实）、contentHash（freshness 判据）。
- 防御上限（`INGESTION_LIMITS`）：块 20000 / 表格数据行 20000 / 单表格行
  500 / cell 2000 字符 / 图 200——截断进 notes，不静默。
- 持久化 `ParsedDocumentStore`：`sources/parsed/<id>.document.json`（原子
  写，损坏容忍为 null 重建）+ `sources/figures/<id>/`（图片资产，随条目
  删除清理）。derived artifact 口径与 chunk 产物一致：可删可重建。

## 5. PDF 现在能解析什么（M10.1B）

- 正文：阅读顺序保持（docling 版面序 = 块数组序；chunker 投影按连续段
  分组，同名节再现不跨段合并）。
- 页码 provenance：全部块（161/161 实测）。
- 章节：docling section_header → provenance.section（实测 title/Abstract/
  "1 Introduction"…"3.1 Encoder and Decoder Stacks"）。
- 表格：TableFormer 结构化网格（headers/rows）+ 题注 + 页码 + bbox；
  chunker 把表格渲染为 `h1 | h2 | …` 行列投影文本进 RAG（可检索），
  结构化本体在 blocks 中。
- Figure：检测 + 页码 + bbox + 题注 + 抽取 PNG 资产（`generate_picture_
  images`，2x scale）。**不做视觉理解 / 不生成图片（M10.2 范围）**。
- Formula：默认关闭 formula enrichment（额外模型）；未开启时块仍登记
  （页码/bbox/ref），LaTeX 留空不伪造。`--formulas` 开关已预留。
- OCR：`do_ocr=False`（确定性纪律）。扫描件 → 文本稀疏 + notes 说明，
  如实降级不猜内容。

## 6. CSV/XLSX → Evidence（M10.1C/D）

不把每个 cell 自动写进 EvidenceStore。链路：

```
CSV/XLSX → structured_record 块（file/sheet/row/column provenance）
        → GET /sources/:id/records（用户浏览候选事实）
        → POST /sources/:id/records/evidence（用户确认某行某列）
        → EvidenceStore.append（既有通道， createdBy="user"）
```

确认时服务端做**机械值校验**：claim 必须真的提到该单元格的值（子串或
数值等价——"82.40" ≡ "82.4"），否则 `EVIDENCE_VALUE_MISMATCH`(422)——
登记的数值必须真的在那个格子里，防手填报错值。

产出的 Evidence 字段：

- `verificationLevel = "user_confirmed"`、`verificationStatus = "unverified"`、
  `verificationMethod = "user-confirmed:experiment-data"`；
- `quote` = 原始单元格值（≤2000）；`source` = {sourceId, title=文件名}；
- `location` = {sheet?, row, column}（EvidenceLocation 最小扩展了
  sheet/row/column 三个 optional 字段，校验同 page 口径）。

**语义边界（§8.5-R1）**：user_confirmed ≠ grounded_verified。分级判定
（`classifyEvidence` / `isFormalEvidence`）**零改动复用**——user_confirmed
证据 status=unverified，不满足 verified+sourceId+chunk 锚点三件套，
因此：
- 不进 Writer/Reviewer 的 formal 池（`selectForWriting` 排除，实测
  excluded.legacyUnverified 计数）；
- 不被解释为「已被外部文献机械验证」；
- 但 claim/summary/quote 进入 factPreservation 的 evidenceTexts——
  用户实验数字获得修订授权链能力（这是 W-1 缺口的兑现），而文献事实
  的授权仍走 verified 证据路径，互不污染。

Manual Fact（M10.1D）：`POST /evidence` 既有通道保持不变（手填，无机械
校验）；records/evidence 是它的「带 provenance + 值校验」强化版，两者
共存不重复造系统。

## 7. 降级与失败策略（不静默）

```
PDF ingest:
  DoclingParser ──不可用(未装/解释器缺失)──→ LegacyPdfTextParser
                                             （pymupdf 文本层 → builtin 文本层）
                                             parseMode=text_only
                                             degradedFrom={parser:"docling", reason}
             ──解析失败(损坏/加密/超时/输出异常)──→ status=failed 文档落盘
                                                 （note 带原因；重试=再调 ingest）
CSV/XLSX:    解析失败（空文件/NUL/损坏 xlsx）→ status=failed 文档落盘，上传不因此失败
```

- 上传响应如实携带 ingestion 汇总（csv/xlsx 内联结果；pdf= pending 后台）。
- `GET /document` 未解析/过期 → `document:null` + 提示（不伪造空文档）。
- chunker 只消费 structured+非 failed 产物；text_only / failed / 缺失 →
  走既有路径（pymupdf/builtin/纯文本），行为与 M6.4 完全一致。
- child process 边界：execFile 无 shell；timeout（docling 600s /
  pymupdf 60s）+ maxBuffer（128MB）；stdout 协议取末行 JSON；路径注入 /
  越界沿用 SourceStore 文件名安全化 + 上传体积上限（20MB）。

## 9. 当前限制（如实）

1. **PDF 后台解析无进度推送**：上传返回 pending，结果经 GET /document /
   POST /ingest 查询（轮询）。SSE 进度属后续。
2. **OCR 关闭**：扫描件文本稀疏、如实降级；开启 OCR（docling 支持 RapidOCR）
   需要额外的确定性权衡，未在本轮引入。
3. **Formula LaTeX 默认不启用**（需额外模型下载；`--formulas` 已预留）。
4. **表格合并单元格**：docling dataframe 导出对合并单元格取主值；exceljs
   同样只有主格有值——如实，不重构。
5. **exceljs 零单元格空行不物化**：exceljs 写出的文件里 addRow([]) 行不
   占行号；真实 Excel 文件空行物化、行号保持。读取侧始终跟随 r 编号。
6. **CSV 无列类型**：全部字符串（数值等价只在确认校验时做归一）。
7. **UI 未动**：本轮以 API + 自动测试 + curl 验证（指令明确 UI 非主任务）。
   上传/文献库页面不变（xlsx/csv 会被现有上传控件接受——白名单已扩展）。
8. **docling 首次运行需要网络**（模型下载）；离线部署 = 永久 text_only
   降级（显式、可用）。
9. `classifyEvidence` 把 user_confirmed 记录计为 `legacy_unverified`
   （派生标识按 status 判定，未为 user_confirmed 单列类）——分级语义正确
   （formal 排除），仅统计口径粗糙，后续需要时再收口。
