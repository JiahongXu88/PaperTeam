# M9.7.2 Writer Evidence 审计（只读分析）

> 2026-09-23，基线 = `main` @ `7bd025b`（M9.7.1 GLM-5.3 baseline 之上）。
> 目的：回答「Evidence → Citation key → Writer → references.bib 在哪一步断开」，
> 为 Evidence-backed Writer Activation（只增强 Writer 输入）提供改动面清单。
> 纪律：本文件为只读审计产物，审计期间零源码改动。

## 0. 结论（先说答案）

**链路没有机械断裂——断的是 prompt 政策层。**

M9.7.1 baseline 的 17.6% coverage 不是任何环节 bug 的结果：Evidence 注入、
key 解析、bib 渲染、coverage 计算全链路通畅（M9.7.1 §6 抽查 10/10 可追溯）。
真正的断点是 `buildSectionPrompt` 的**引用白名单把 17 个 key 平铺呈现**：
有 verified evidence 支撑的 3 个 key 与 LLM 回忆的 14 个 key 在 Writer 眼里
完全同权，而「优先使用 Evidence」只是一句软建议（规则 3），紧随其后的
规则 4 却无条件授权全部 key。GLM-5.3 写综述时自然大量引用自己回忆的
条目——那 14 条本来就是同类模型回忆出来的，写起来最顺手。

### 1.2 manuscript generation 流程（`workflow/definitions.ts` `writingSectionsStage`，L2298-2379）

```
loadOutline → requireResearchArtifact
→ evidenceSelection.selectForWriting(projectId)          // L2314：formal 池
→ buildCanonicalBibliography(services, projectId)        // L2317：17 key
→ for each section: writer.writeSection({ section, outline,
        evidence: formal, bibliography: canonical })      // L2325
→ manuscript.writeMainTex → syncReferencesBib            // L2344-2349
→ revisions.commit("writing.sections")
```

- **evidence 已传入**：`evidence = evidenceSelection.formal`（verified + sourceId + chunk 锚点，`FORMAL_EVIDENCE_LIMIT = 20`）。M9.7.1 的 14 条全部进入每节 prompt（14 ≤ 20，**不存在截断丢失**）。
- **bibliography 来源**：`buildCanonicalBibliography`（L1443-1455）= `buildBibliographyFromSources(文献库 3 条)` ∪ `mergeArtifactBibliography(LLM 回忆 15 条)` → `assignCitationKeys` 确定性 key → 17 条。
- 修订链 bibliography 更宽：`manuscriptBibliography`（L1504-1527）= canonical ∪ references.bib 现存条目（含历史引用过的 key——防止把合法引用当违规删除，2026-09-14 B2/A2 教训）。

### 1.3 citation context 在 prompt 里的实际形态（`buildSectionPrompt`）

```
输出要求：
3. 论述优先使用下方 Evidence 支撑（…引用时优先使用行内标注的 cite key）；
   证据不足时显式弱化表述或标注，不为凑字虚构数据、结论或引用。
4. 只允许引用以下参考文献 key：key1, key2, …, key17     ← 平铺，无分组
…
===== 可用 Evidence（已核验 verified 快照）=====
- [E001]（cite: yao2023react）claim 截断 150 字（引文："quote 截断 120 字"）
…（14 行，每行都只指向 3 个 key 之一）
（evidence_query 工具指引）
```

`renderEvidenceLines`（L71-86）逐条调用 `resolveEvidenceCitationKey` 标注 cite key
——**这个标注是对的**，问题在于它与规则 4 的白名单没有任何联动：14 条无证据
key 同样列在「只允许引用」清单里，且排面上更醒目。

## 2. Evidence 现有结构（`backend/src/evidence/EvidenceStore.ts`）

### 2.1 EvidenceRecord（L51-69）

| 字段 | M9.7.1 baseline 实际值 |
| --- | --- |
| `id` | E001…（14 条） |
| `claim` / `quote` | 论断 + 全文逐字引文（三段核验 quote=exact） |

| `location.chunk` | chunkId 锚点，形如 `S001:SEC01:0001:e6aa882f99`（`sources/chunks/*.jsonl` 定位） |
| `verificationStatus` | 全部 `verified` |
| `supportStrength` / `verificationLevel` | 全部 `direct` / `fulltext` |

### 2.2 formal 判定与选择（`EvidenceSelectionService.ts`）

- `isFormalEvidence`（L40-46）= `verified` && `sourceId` && `chunk` 三件套——M6.6 §10 单一口径，writer 工具视图（`evidence_query` formalOnly）与 workflow 选择层共用。
- `selectForWriting`（L95-122）：direct 优先排序，limit 20。legacy unverified（4 条）被排除，不进 prompt。

### 2.3 citation key resolution（`citation/bibliography.ts` `resolveEvidenceCitationKey`，L394-406）

```
EvidenceRecord.source.sourceId ──精确匹配 bib 条目 sourceId 字段──→ key
（miss）→ EvidenceSelectionService.matchBibliographyKey：DOI 精确 → 归一标题(+年份)
（仍 miss）→ null（该证据行不标注 cite，不猜测）
```

M9.7.1 里 3 篇入库条目自带 sourceId，14 条证据全部精确解析到
yao2023react / shinn2023reflexion / schick2023toolformer。**该函数同时在
`renderEvidenceLines`（Writer prompt）与 `computeEvidenceCitationCoverage`（gate）
两处使用，口径同源——覆盖统计与 Writer 所见一致，无双重标准。**

## 3. Citation pipeline 全链与断点定位

```
Evidence(14 verified)                                        [EvidenceStore]
   │ resolveEvidenceCitationKey（sourceId 精确）               ✓ 通
   ▼
Writer prompt：14 行 digest，每行（cite: key）                  ✓ 通（L71-86）
   │  ⚠ 断点①：白名单平铺——17 key 同权呈现，无 evidence 分组
   │  ⚠ 断点②：规则 3「优先使用」是软建议，无任何行为约束力
   ▼
LLM 自由选择 → 59 处 \cite 覆盖全部 17 key                     （GLM-5.3 行为）
   │
   ▼
syncReferencesBib → filterByCitedKeys(17) → references.bib     ✓ 通（L1471-1495）
   │
   ▼
citation.verify：missing/hallucinated/unused = 0（结构层全对）  ✓ 通
computeEvidenceCitationCoverage：3/17 = 17.6%                  ✓ 通（如实呈现）
```

### 断点明细（全部在政策/激励层，非机械层）

| # | 位置 | 问题 |
| --- | --- | --- |
| ① | `buildSectionPrompt` L961-964 规则 4 | 白名单平铺 17 key：evidence-backed 3 个与 LLM 回忆 14 个零区分。回忆条目标题/年份本身就是模型熟悉的，引用阻力最小 |
| ② | 同上规则 3 | 「优先使用下方 Evidence」无配套约束；与规则 4 合读等于「优先 A，但 B 也随便用」 |
| ③ | `buildOutlinePrompt` L926-929 | 大纲层同样平铺：keyPoints 规划阶段就未向证据倾斜，正文按大纲展开自然继承脱节 |
| ④ | `buildRevisePrompt` L731-735 规则 9/10 | 修订白名单同样平铺 + 规则 10「保留现有 \cite」**把无证据引用保护起来**——修订轮结构性无法收敛 coverage（M9.7.1 §12-2：Writer 响应「补证据」反而删了 7 个 key） |
| ⑤ | gates.ts L472-485 | `citations_evidence_backed` 只呈现不阻断（`requireEvidenceBackedCitations` 默认非强制），且**不回流**到任何 Writer 输入——无反馈回路 |
| ⑥ | 次级 | `resolveEvidenceCitationKey` 返回 null 时该证据行无 cite 标注（Writer 无从引用）；arXiv enrich 失败时（M9.7.1 §12-8）artifact 条目无 sourceId，是潜在退化点（本次未触发：3 篇入库条目 sourceId 齐备） |

### 对照：M9.6 为什么是 100%

M9.6 的 2/2 = 100% 是**结构性**的：当时 canonical bibliography 只有 2 条
（全部有 evidence），Writer 根本没有无证据 key 可选。不是 prompt 政策起了作用。
一旦 bibliography 含回忆条目（M9.7.1：15/17），旧 prompt 立即退化到 17.6%。

## 4. 修复设计（M9.7.2 实施约束下的方案）

约束：不新增 Agent、不改 Runtime、不改 Workflow——**只增强 Writer 输入**
（`WriterService.ts` 的 prompt 构造层；evidence 与 bibliography 参数已由
`writing.sections` / `revision.revise` 传入，无需动调用方）。

### 4.1 核心：Verified Evidence Context + key 分组

1. **key 分组（prompt 派生视图，不落存储）**：构造 prompt 时用
   `resolveEvidenceCitationKey`（与 coverage 判定同一解析链）把 bibliography
   切成 A 组（≥1 条 formal evidence 命中）/ B 组（无证据支撑）；
2. **规则重写**：事实性论断（机制、方法、数值、结论）的引用必须取自 A 组；
   B 组只可用于泛指性背景陈述（领域概述、广为人知概念），不得支撑具体
   事实/数值/结论；证据不足的论断弱化或删除，不得改引 B 组充数；
3. **块头更名**：`===== 可用 Evidence =====` → `===== Verified Evidence Context =====`，
   digest 行格式（`- [E-id]（cite: key）claim…`）保持不变——两处测试契约
   （`WriterService.test.ts` L183、`deterministicBibliography.test.ts` L271）不受破坏；
4. **同一分组注入三个写作面**：`buildSectionPrompt`（规则 4）、
   `buildRevisePrompt`（规则 9，修订单独叠加「B 组引用保持现状但不得新增」的
   保序语义，与规则 10 引用保护不冲突）、`buildOutlinePrompt`（规则 3）。
   style-polish / repair / legacy write / 摘要修订不注入（它们本就不产生引用）。

### 4.2 边界行为（预注册）

| 场景 | 行为 |
| --- | --- |
| bibliography 为空 | 维持现状：「（无可用文献：不要使用 \cite）」 |
| A 组空、B 组非空 | A 组行明示「当前无任何 key 有 verified evidence 支撑」；B 组仅限背景性提及，事实论断要求弱化——不阻断写作（evidence.ground 失败不该烧掉整轮 run） |
| B 组空（M9.6 形态） | 只渲染 A 组行——行为与现状等价（全部 key 本就有证据） |
| coverage gate | **不改**：`requireEvidenceBackedCitations` 阈值与呈现语义维持现状（M9.7.1 §13-3 明确「先引导、积累对照数据后再决定是否升级为扣分项」） |

### 4.3 明确不做（本轮红线）

- 不把 B 组从白名单剔除（综述引用面骤降到 3 key 会伤学术形态；task 目标是
  「优先」而非「只许」）；
- 不动 `FORMAL_EVIDENCE_LIMIT` / quote 截断长度（M9.7.1 无截断丢失证据，
  14 ≤ 20 全量注入）；
- 不动 Workflow / Runtime / Quality Gate 阈值 / EvidenceStore schema；
- 不新增配置开关（prompt 层增强，无条件生效，保持确定性）。
