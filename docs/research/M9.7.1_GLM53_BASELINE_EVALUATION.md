## 12. Failure Cases

1. **修订协议违规（run1 致命失败）**：`revision item transitions 包含重复 id` ×2 次
   尝试（每次 ~10 min 模型执行后被确定性解析拒绝）→ run failed。Writer 的
   `%%%PT-OUTCOMES%%%` 协议输出对同一 item 重复上报 transition，GLM-5.3 协议遵循
   不稳定；
2. **Writer 修订的引用删除倾向（run2 r2）**：响应审稿「补证据」时选择**删除 7 个
   引用 key**（besta2024graph/boiko2023autonomous/hong2023metagpt/huang2023large/
   qin2024tool/yuan2024judge/zhou2023webarena）而非补证，Citation Preservation
   拦截（rejected 16 条目）后经 HITL approve 放行——M9.6 §12-1 同型问题在 GLM-5.3
   上重现且更严重（M9.6 删数值，本次删引用 + 数值）；
3. **事实漂移（run2 r2/r3）**：「2022年 → 1（原 2022年）」年份改写、无据新增
   「12次」「2025年」等数值——Fact Preservation 拦截并记入 gate 失败原因；
4. **REGRESSION 不收敛（run2 r3）**：修订后 UNSUPPORTED 7→15、critical 0→1、
   citation missing 0→7（Writer 重新引用了已从 bib 裁剪的 key，自相矛盾），修订
   循环正确终止于 REGRESSION；
5. **rev7 构建失败（确定性防线胜利）**：7 个 undefined citations 触发编译终检，
   「技术上能出 PDF 但参考文献不完整」的产物被正确拒绝——评估者未绕过，走
   restore 恢复干净 rev6 后合法重建；
6. **孤儿章节文件**：修订后 sections/ 残留 5 个不被 main.tex input 的旧 .tex
   （evaluation/framework/reasoning-acting/tool-invocation/verbal-reflection），
   不进编译但污染工作区、干扰 naive 统计口径；
7. **restore 后 citation report 不重算**：r4 手动 review/gate 读到 r3 时的
   citation-report（missing=7），对实际干净的 rev8 产生假阳性 FAIL（审稿人文本里
   同时看到「cited=24 missing=7」与「正文仅 17 key」两份矛盾的口径并如实报告）；
8. **arXiv 元数据链失败**：enrich 3/3 未定论（arxiv provider degraded，3 连败），
   bib 条目缺 sourceId 追溯字段、evidence 三段核验 metadata=unresolved——整条
   引用链退化为 DOI-only 追溯（本次 3 篇均为知名论文，作者/年份由 Writer
   bibliography 回忆正确给出，风险未兑现，但这是运气不是保障）。

## 13. Improvement Opportunities

1. **修订协议容错/自愈（P0）**：`PT-OUTCOMES` transitions 重复 id 应可确定性去重
   （同 id 后报覆盖先报）或回滚重试单节，而不是烧掉整轮 run（run1 损失 44.7 min /
   ~$1.7）；
2. **Writer「恢复优先于删除」纪律（M9.6 §13-1 重申，GLM-5.3 数据加强）**：修订
   prompt 需硬性禁止无授权删除引用 key 与改写数值；可在 reviseSection 输入侧
   确定性注入「本轮禁删 key 白名单 + 数值白名单」；
3. **引用-证据对齐策略**：evidence-backed coverage 17.6%（14 条证据只覆盖 3/17
   key）——或引导 Writer 优先引用有 verified evidence 的 key，或将
   `requireEvidenceBackedCitations` 升级为软性扣分项（继续积累对照数据后决策）；
4. **restore 链联动重算**：恢复历史修订时自动重跑 citation extract/verify，消除
   r4 假阳性（§12-7）；
5. **修订后孤儿文件清理**：revise 完成后清理未被 main.tex input 的 section 文件，
   或在 build 前校验 input 链完整性；
6. **arXiv 元数据 resolver 降级策略**：PDF 首页文本兜底解析标题/年份（arXiv
   PDF 首行即 title），或 S2/CrossRef by-arxivId 反查；
7. **Baseline 对照建议（面向 M9.7.2+）**：未来 Claude/GPT 复测时保持本报告 §2 任务
   与 §1 配置不变，重点对比——run 成功率（1/2）、修订协议违规、REGRESSION 收敛、
   evidence-backed coverage、UNSUPPORTED claim 轨迹（7→8→15 vs 8）、$/千字成本。

## Verdict

**M9.7.1 完成**：GLM-5.3 在真实完整流程上产出了一篇结构完整（10 节 + 摘要 +
17 条真实渲染参考文献）、结构层引用全对（missing/hallucinated/unused 全零）、
证据链 100% 可追溯抽查通过的 10 页 Draft PDF；同时暴露了三个系统性弱点——修订
协议输出违规（1/2 run 致命失败）、修订期引用/数值破坏（Preservation 防线全部
拦下但烧掉收敛性，最终 REGRESSION）、引用面与证据池脱节（17.6% evidence-backed）。
所有质量防线（Citation/Fact Preservation、编译终检、Gate、Finalize）在真实故障
注入下全部正确工作，无一被绕过；评估全程零代码改动、零标准降低。
