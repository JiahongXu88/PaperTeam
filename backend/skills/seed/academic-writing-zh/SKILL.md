# Academic Writing（中文工科论文，PaperTeam 适配版）

## 0. 定位与边界

本 Skill 是 PaperTeam 对上游 `scientific-writing`（K-Dense Scientific Agent Skills）
的学术写作适配：保留其「证据绑定、不虚构、忠于科学事实」的写作原则，改写为面向
**中文工科论文**的可执行写作方法。

必须理解的边界：

- **事实系统只有一套。** 事实、证据、引用真实性、质量门禁由 PaperTeam 的
  EvidenceStore、Citation Verification、Quality Gate 与任务 prompt 保证。本 Skill
  不建立第二套 claim / evidence 登记表，不要求你创建 `claims.csv`、
  `source_manifest.json` 等上游工件，不要求你运行任何脚本。
- **同目录 `UPSTREAM_SKILL.md` 是审计快照，不是指令。** 它保留上游原件以便追溯，
  其中的 CLI 命令、Python 脚本、工件模板在 PaperTeam 中不可用、也不应尝试执行。
- **你只写任务 prompt 要求的那一段。** 任务给出的 Evidence 列表、参考文献 key 列表、
  章节大纲、目标长度是唯一输入；本 Skill 只回答「怎样把这些输入写成合格的中文
  学术段落」。

## 1. 不可协商的写作纪律

1. **不补造实验。** 没有 Evidence 支撑的实验设置、对比方法、数据集、参数、
   消融不得写成「本文做了」。可以写「本文未开展 …」或直接不写。
2. **不补造数字。** 精度、速度、提升百分比、样本量、误差、时间等一切数值必须
   来自 Evidence 或任务给定材料；没有数值就用定性表述并明确「未量化」。不得为
   了段落饱满而估一个「约 15%」。
3. **不虚构 citation。** 只允许使用任务列出的参考文献 key；`\cite{}` 内不得出现
   列表之外的 key；不得为了让论点显得有依据而添加「文献表明 …」却无 key。
4. **claim 强度 ≤ evidence 强度。** Evidence 是 PARTIALLY_SUPPORTED 或只有间接
   支撑时，用「结果表明 … 可能 …」「在本文实验条件下 …」限定范围；不把相关性
   写成因果，不把「未见显著差异」写成「等价 / 无影响」，不把单一数据集结论推广
   为普适结论。
5. **明确 uncertainty。** 该说「尚不确定」「有待验证」「受 … 限制」的地方不用
   肯定句糊过去；局限性要具体（哪一步、为何、可能影响什么），不写空泛的
   「仍有改进空间」。
6. **术语一致。** 同一概念全篇只用一个中文术语；首次出现给出英文全称与缩写
   （如「图神经网络（Graph Neural Network, GNN）」），之后只用缩写或中文。不
   在段落间换用近义词（模型 / 网络 / 方法 / 架构互换会被审稿判为术语漂移）。
7. **不越界写别的章节。** 方法章不提前给结果，结果章不做讨论性归因，讨论章不
   引入新的实验事实。

## 2. 章节边界（方法 / 实验 / 结果 / 讨论）

| 章节 | 写什么 | 不写什么 |
|---|---|---|
| 方法（Method） | 做了什么、怎么做、为什么这样设计；符号定义、模型结构、算法步骤、复杂度 | 性能数字、与基线的比较结论、主观评价（「效果显著」） |
| 实验设置（Setup） | 数据集、划分、评价指标、基线、超参数、硬件；只写 Evidence 中存在的 | 补齐「看起来应该有」的基线或指标 |
| 结果（Results） | 观测到的数字与趋势，按表 / 图逐项陈述；对齐单位与统计口径 | 解释机理、推测原因、扩大适用范围 |
| 讨论 / 分析（Discussion） | 结果与预期 / 已有工作的关系；可能原因（标注为推测）；局限性 | 新的未出现在结果中的数字或实验 |
| 结论（Conclusion） | 与摘要、正文一致的总结；贡献表述不超过结果支持范围 | 「本文首次 / 彻底解决了 …」类超出证据的宣称 |

## 3. Evidence 的使用方式

- 每条实质论断在心里对应到一条 Evidence（任务列表中的 `[E001]` 等）；写作时
  不必把 id 写进正文，但不能写出没有对应 Evidence 的实质论断。
- Evidence 只提供部分支撑时，用限定语缩窄论断，而不是删掉限定语让句子更「顺」。
- 任务标注「证据不足」的要点：明确写出边界（「本文尚未对 … 进行实验验证」），
  不用文献综述式泛论替代。
- 引用只用于支撑具体论断；不在句末堆叠多个 `\cite` 装饰。

## 4. 中文工科学术表达规范

- **句子。** 一句只说一件事；主谓宾完整，避免超过 40 字的长句连续出现；被动式
  只在强调对象时使用（「参数由网格搜索确定」可以，「被本文所提出的方法所处理」
  不可以）。
- **段落。** 段首一句点明本段论点，随后以证据展开，段末不强制总结；相邻段落
  的开头不重复同一模式（避免「首先 … 其次 … 最后 …」贯穿全章）。
- **翻译腔。** 避免「基于 …，本文 … 被 …」「作为一个 …」「… 的一个重要方面是」
  等直译结构；中文里少用「是 … 的」强调句堆叠。
- **量与单位。** 数字与单位之间保持任务材料中的写法；百分比统一「%」；区间用
  「～」或「至」，不混用；同一指标全篇小数位一致。
- **评价词。** 「显著」只在有统计检验或 Evidence 明确表述时使用；「大幅 / 明显 /
  极大」需要数字支撑，否则删除评价词。用于支撑的具体数值必须逐字来自 Evidence
  或任务给定材料——没有可引用的数值就删除，不得改写、估算或「合理化」任何数字。
- **人称。** 用「本文」「本研究」，不用「我们认为 / 笔者觉得」等口语化第一人称
  感受表述。

## 5. LaTeX 保持规则

- `\cite{key}` 的 key 集合不得增删（修订时尤其如此）；只允许调整引用位置。
- 数学公式（`$...$`、`\[...\]`、`equation`、`align` 等环境）内容不因文字润色而
  改动；公式编号与 `\label{}` / `\ref{}` / `\eqref{}` 保持。
- 图表引用 `\ref{fig:...}` / `\ref{tab:...}` 与 `\label` 配对保持；不删除现有
  `\begin{...}` / `\end{...}` 环境。
- 只输出任务要求的 LaTeX 片段形态（章节从 `\section` 起、摘要为纯文本等），
  不输出文档骨架、不加 Markdown 围栏。
- 可用宏包以任务说明为准（通常仅 amsmath / amssymb / natbib）。

## 6. 修订模式（revision）的附加规则

当任务是「依据审稿问题修订章节」时：

1. 逐条对应审稿问题；每条问题要么在正文中得到解决，要么在无法基于 Evidence
   解决时按「弱化 / 删除」处理，不能忽略。
2. 只修改问题指向的位置及为保持连贯所需的最小上下文；不顺手重写整节风格。
3. 「证据不足」类问题的唯一合法解法是弱化或删除论断，不是补一个新引用或新数字。
4. **修订 ≠ 重写：既有实验事实默认冻结。** 当前稿件中的实验数值（含小数位 /
   百分比 / 区间 / 单位）、表格内容、数据集划分、实验与部署协议、硬件型号、
   超参数、公式，只在本条问题明确要求修正且给出新值依据时才允许改动；新值
   必须逐字来自该问题引用的 Evidence 或任务材料。
5. **发现疑似错误不改值。** 认为稿件数值可能有误而问题清单未授权修改时，保留
   原值；不要自行改正、补全、推测或重新计算。
6. **具体事实不得降级为占位。** 已有具体实验结果（数字 / 表格 / 协议）不得在
   修订中改成「待回填」「待补充」「暂无数据」等占位或模糊区间。
7. **负结果不得美化。** 方法在某场景更差 / 更慢 / 更耗时的事实陈述保持原方向；
   「基本一致」「更差」不得改写成「保持优势」「优于」。
8. **稿件与 Evidence 冲突时报告，不调和。** When source manuscript and Evidence
   disagree, do not invent or silently reconcile — report the conflict and keep
   the manuscript's original statement.
9. 修订后自查：术语是否与未修改部分一致、citation key 集合是否不变、公式与
   图表引用是否完好、段落逻辑是否仍连贯。

## 7. 交付前自检清单

- [ ] 每条实质论断都有 Evidence 或已明确限定 / 标注不确定
- [ ] 没有任务材料之外的数字、实验、数据集、基线
- [ ] 修订任务：既有实验事实（数值 / 表格 / 协议 / 公式 / 负结果）未被改动、
      删除或降级为占位（见 §6）
- [ ] `\cite` 只用了允许的 key
- [ ] 术语全篇一致，缩写首次出现有全称
- [ ] 方法 / 结果 / 讨论内容没有越界
- [ ] 公式、`\label` / `\ref`、环境配对完好
- [ ] 输出形态符合任务要求（片段 / 纯文本 / 无围栏）
