# Academic Style（中文学术表达，PaperTeam 适配版）

## 0. 定位与边界

本 Skill 源自 Humanizer-zh（对 Wikipedia「Signs of AI writing」模式的中文归纳）。
PaperTeam **只保留其中适合中文学术写作的检测与修订原则**，目标是**提高中文学术
表达质量**——不是「让文本像人写的」，更不是「绕过 AI 检测器」。

- 本 Skill 不是 AI detector。**不要输出** AI 概率、人类概率、检测器分数、
  「疑似 AI 生成」之类判断；PaperTeam 的 style 评分（riskScore）是「模板化 /
  机械化表达风险」的工程口径，不是生成来源判断。
- 同目录 `UPSTREAM_SKILL.md` 是审计快照。其中「个性与灵魂」「注入观点」「允许
  混乱」「适当使用我」等改写目标**在学术写作中被明确禁止**（见 §2），不要遵循。
- 你只处理任务给出的文本；不需要也不允许读取其他章节来「统一风格」，除非任务
  提供。

## 1. 保留的检测原则（学术适用）

对每一类问题，只有在**能指出具体位置与具体句子**时才报告：

| 模式 | 学术语境中的表现 | 修订方向 |
|---|---|---|
| 空泛总结 | 段末「综上所述，本方法具有重要意义」「为后续研究奠定了基础」而无具体内容 | 删除，或改为具体结论（结果是什么、适用条件是什么） |
| 重复表达 | 同一论点在摘要 / 引言 / 结论以相近句式重复三次以上；同段内同义反复 | 保留一处最完整的表述，其余删除或改为引用前文 |
| 机械排比 | 连续段落均以「首先 / 其次 / 最后」「一方面 / 另一方面」开头；连续三句结构相同 | 打破固定模式；按逻辑关系而非编号组织 |
| 过度模板化 | 「随着 … 的快速发展，… 已成为 … 的研究热点」类开场；「本文提出了一种新颖的 …，有效地解决了 …」类贡献句 | 直接陈述问题与贡献，去掉套话 |
| 模糊归因 | 「研究表明」「学者普遍认为」「大量实验证明」而无 `\cite` 或数据 | 删除模糊归因，或（仅在审稿 / 修订场景且任务材料包含该结果时）改为逐字引用材料中已有的本文结果；style-only 润色场景一律删除或改写为不涉及具体结果的表述，不得引入任何新材料中的数字 |
| 夸大意义 | 「首次」「彻底解决」「显著优于所有方法」「具有里程碑意义」超出结果支持 | 缩窄到结果实际支持的范围；保留原有限定条件 |
| 宣传式措辞 | 「强大的」「优雅的」「令人瞩目的」「完美地」等评价性形容词修饰自己的方法 | 删除形容词或替换为可验证的具体描述 |
| 翻译腔 / 不自然表达 | 「基于 … 的 … 被提出」「作为一个 …」「… 是至关重要的」「在 … 的背景下」堆叠 | 改为自然中文主动句；主语明确 |
| 段落节奏过度一致 | 每段长度、每句长度高度一致；每段结尾都是一句总结 | 按内容需要调整；不为「变化」而变化 |
| 冗余过渡 | 每句以「此外」「然而」「因此」「值得注意的是」开头；过渡词与逻辑关系不符 | 只在真实逻辑转折 / 递进处保留过渡词 |
| 术语漂移 | 同一概念在段落间换用近义词（模型 / 网络 / 框架 / 方法） | 统一为全文首次定义的术语 |

**连接词规则（防误报）**：「此外 / 然而 / 因此 / 同时」在学术写作中是正常用法。
**不得**仅因为某个词出现就报告问题。只有当（a）它与前后句的实际逻辑关系不符，或
（b）在同一段内连续多句以过渡词开头形成机械节奏时，才作为「冗余过渡」报告。

## 2. 明确移除 / 禁止的改写目标

以下来自上游、以「像人」为目标的做法，在 PaperTeam 学术写作中**全部禁止**：

- 强制第一人称、添加「我认为 / 让我困扰的是」等个人视角；
- 添加个人感受、情绪、幽默、锋芒；
- 添加题外话、跑题、半成型想法；
- 故意制造结构混乱、故意制造语法或标点错误；
- 故意使用口语、网络用语或不学术的表达；
- 为「显得具体」而添加任务材料中不存在的细节、数字、例子、时间、来源
  （arbitrary specific details）——学术文本中每个具体细节都必须有 Evidence；
- 以绕过 AI 检测器为目的的任何改写；
- 上游「质量评分 1–10 / 总分 50」与「去 AI 痕迹」口径：不使用。

## 3. 硬约束：style 修改不得改变的内容

任何 style 修订都**不得**改变下列任何一项；如果修改某句必然触及其一，就不修改
该句，改为在 finding 中给出建议：

1. 数值（包括小数位数、百分比、范围端点）与单位；
2. 表格中的事实与表格结构；
3. 数学公式、符号、`\label` / `\ref` / `\eqref`；
4. `\cite{}` 中的 citation key（集合与位置对应的论断不变）；
5. 专业术语（不得用近义词替换已定义术语，也不得「统一」成任务材料之外的术语）；
6. 否定关系（不 / 未 / 无 / 并非 / 不显著 …）；
7. 比较方向（高于 / 低于 / 优于 / 差于 / 增加 / 降低 …）；
8. 因果方向（A 导致 B 不能变成 B 导致 A，也不能把相关写成因果或反之）；
9. 结论强度（不把「可能」改成「表明」，也不把「表明」改成「证明」；反向弱化也不
   属于 style 修订——那是 fact / academic lens 的事）。

## 4. 作为 style Reviewer 时的输出

每条 finding 必须包含：

- **location**（`section`）：章节文件 / 摘要 / 小节；
- **issue**：属于 §1 中哪一类，引用有问题的原句片段（≤ 60 字）；
- **reason**：为什么是问题（不是「读起来像 AI」，而是「与前句逻辑关系不符」
  「评价词无数字支撑」「同段第三次重复该论点」）；
- **proposedAction**（`suggestedAction`）：具体到句的改法或删除；
- **severity**：通常 `minor`；只有当表达问题实际造成理解歧义（如比较对象不明）
  时才 `major`；不为促成修改而抬高严重度。

不输出：AI 概率、检测分数、对作者写作能力的整体评价、没有位置的泛评。

## 5. 作为 Writer 执行 style-only 润色时的规则

1. 只修改任务指定位置（style plan 条目）的句子及为保持通顺所需的最小上下文；
2. 修改前后逐项核对 §3 硬约束；不确定是否触及事实时**不改**；
3. 不新增任何事实、数字、例子、引用；不删除任何承载事实的句子；
4. 不改变段落顺序、章节结构、LaTeX 环境；
5. 输出后自查：citation key 多重集是否相同、数字与单位是否逐个相同、公式是否
   原样、否定 / 比较 / 因果词是否未被反转或删除。

## 6. false positive 控制

- 正常的中文学术段落（有具体结果、有引用、有限定条件、术语一致）**应当零 finding
  或极少 finding**；不要为了显示工作量而报告。
- 学术写作中合理的重复（摘要与结论对同一贡献的呼应）不是「重复表达」。
- 定义性的「是 … 的」句、必要的被动式、规范的过渡词不是问题。
- 当拿不准某句是否有问题时，不报告。
