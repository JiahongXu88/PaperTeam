# ADR：M6 Search / Academic Search / RAG / Evidence 架构（M6.1 冻结）

> 状态：**accepted（2026-09-16，M6.1 架构冻结）** · 决策登记：[../DECISIONS.md](../DECISIONS.md) D-0033
> 证据基础：[M6.1_SEARCH_RAG_OSS_ANALYSIS.md](M6.1_SEARCH_RAG_OSS_ANALYSIS.md)（6 开源项目源码分析 + PaperTeam 盘点）
> 本 ADR 冻结架构决策；实现排期见「Implementation order」，M6.2 起逐项落地。

## 1. Context

M6 要给 PaperTeam 增加 Research Discovery 能力：Web Search、学术检索、文献
入库、全文获取、项目级检索（RAG）、Evidence 闭环。M6.0 冻结时 PaperTeam 已有：
`ScholarlyResolver`（4 学术 provider + 确定性打分 + 缓存/重试/telemetry）、
`SourceStore`（项目文献库，`AGENT_RETRIEVED` origin 已预留）、`EvidenceStore`
（verificationStatus/supportStrength/verificationLevel + location.chunk）、
Final PDF 的 section-aware chunk 管线、Pi customTools 注入机制（search_papers /
lookup_paper 先例）。缺口：真关键词检索（现 search() 是查证形）、跨源融合
去重、全文获取、sources 库 chunk 化、Web Search、共享 Provider HTTP 基建
（两份重复 fetchJson）。

约束：中国大陆必须可在完全无 Google 的情况下完成主流程；single-user /
local-first / 文件优先（D-0013，不提前引入数据库）；AgentRuntime 不承载
Search/RAG；Retrieved ≠ Verified；不得为「标准 RAG 架构」引入重型外部依赖。

M6.1 对 6 个开源项目做了源码级分析（证据见分析报告 §3-§8），核心输入：
SearXNG（多引擎聚合纪律/打分公式/熔断时长/中国引擎实况）、agent-search
（canonical_url 去重/SSRF 逐跳校验/预算护栏/代码拼参考文献；RAG 主链无 chunk
结构不可依赖）、paper-search-mcp（伪统一反面样本）、aminer-open-skill（AMiner
能力边界与角色判定）、semantic-scholar-mcp（Retry-After/错误分层/共享基建
分层裁定）、openalex-research-mcp（薄原语+厚编排、OpenAlex v1 最小集）。

## 2. Decision（D-0033）

1. **六层能力分离，各自最小接口**：WebSearchProvider / AcademicSearchProvider /
   MetadataResolver（既有 ScholarlyResolver.resolve 语义）/ FullTextResolver /
   LiteratureLibrary（SourceStore 扩展）/ RetrievalService+RetrievalIndex。
   Web 与 Academic 不合并为万能 SearchProvider。
2. **Web Search = SearXNG 独立服务**：PaperTeam 经 HTTP 调用（`GET /search?
   format=json`），SearXNGProvider 是唯一 WebSearchProvider 实现。**不做
   bundled subprocess、不复制其代码**（AGPL 边界 + Python 异构 + 复用既有
   compose 形态）。SearXNG 是 **optional** 能力：不可用时 Web Search 降级为
   unavailable，学术主链路不受影响。
3. **Academic Discovery = 扩展既有 ScholarlyResolver 生态**：新增
   AcademicSearchProvider 接口（真关键词检索语义）；OpenAlex 为 primary，
   S2 为 enrichment/fallback，Crossref/arXiv 保持参与；AMinerProvider 为
   China secondary + enrichment（付费端点默认关闭，免费层先行）。检索与
   核验两个接口分开（search ≠ lookup）。
4. **Crossref = MetadataResolver**（引用核验链路，既有职责不变，不做 discovery
   primary）；**Unpaywall = FullTextResolver**（与 arXiv PDF / OA URL / 用户
   上传并列），绝不进 AcademicSearchProvider。
5. **跨源同一性 = 分层确定性键**（DOI > arXiv ID > PMID > 归一标题+年份+一作
   strong tier > 预印本-正式版合并偏正式版），产出 `SourceIdentity`；多源
   结果融合打分借 SearXNG 倒数排名融合（引擎权重=provider 权重）。
6. **共享 Provider HTTP Infrastructure（ProviderHttpClient）**：统一超时/
   指数退避+抖动/Retry-After 优先（等待有硬帽）/类型化错误（含
   rate_limited(retryAfter)）/TTL 缓存/每 provider 速率档位/熔断
   （连续失败开路+半开探测）/「限流≠宕机」区分。收敛两份 fetchJson；
   provider 特有的只有速率档位、base URL、鉴权、字段映射。
7. **Index 是 Derived State**：chunk 落盘（sources/chunks/<sourceId>.jsonl，
   含 paper/section/page/contentHash 绑定）+ 进程内 lexical 索引（惰性构建、
   可全量重建）+ 可选 dense（EmbeddingProvider 抽象，向量随 chunk 存储旁车
   文件）。**第一版不引入任何 Vector DB / 外部数据库进程**（Milvus/Qdrant/
   Elasticsearch/Redis 全部拒绝；规模 = 每项目几十篇 × 数千 chunk，内存索引
   足够；单用户无并发压力）。**reranker 第一版不做**。
8. **Evidence 边界不变且加严**：SearchResult → CandidateSource → SourceDocument
   → SourceChunk → RetrievedChunk → EvidenceCandidate（quote 逐字来自 chunk，
   确定性校验）→ Verification（quote 匹配 / 元数据核验 / LLM judge 只见真实
   证据）→ EvidenceStore。搜索 snippet 最高支撑 plausible（abstract 级），
   **永远不能直接 verified**；LLM 不得据检索摘要生成事实绕过 quote 校验。
9. **AgentRuntime 不承载 Search/RAG**：检索/抽取/嵌入/索引全部在
   WorkflowOrchestrator 编排的服务层；Agent 经 customTools 消费
   （web_search / search_papers v2 / retrieve 等受控工具，沿用
   scholarlyTools 模式）。
10. **MCP 位置：内部零 MCP**。内部一切走 TypeScript interface + Pi
    customTools；MCP 仅作为远期「对外暴露 PaperTeam 能力给用户的其他 Agent
    客户端」的可选形态（defer，有真实产品需求时单独立项）。
11. **Google 边界**：架构中 Google 不是任何环节的依赖（SearXNG engine 白名单
    不含 Google 亦可工作；学术链路无 Google 组件）。未来 Google engine 只是
    SearXNG 配置项。
12. **零第三方源码进入 PaperTeam**：所有开源项目只借设计（分析报告 §14），
    不复制代码、不加运行时依赖、不做 submodule。

## 3. Architecture（目标架构，M6.2-M6.5 落地后形态）

```text
Researcher（Agent，经 Pi customTools 受控调用）
   │
   ▼
ResearchDiscoveryService（编排 discovery；backend 内）
   │
   ├─ WebSearchService ── WebSearchProvider ── SearXNGProvider ──HTTP──► SearXNG（外部容器，optional）
   │                                        （未来可加其他实现）
   │
   └─ AcademicSearchService ── AcademicSearchProvider（接口）
         ├─ OpenAlexProvider（primary）
         ├─ SemanticScholarProvider（enrichment / fallback）
         ├─ ArxivSearchProvider（preprint）
         └─ AMinerProvider（China secondary + enrichment；免费层先行）
         【勘误 2026-09-20（M7.2）：原图在此列有 CrossrefSearchProvider
          （fallback 参与）——与 §2-4 决策矛盾。D-0033 裁定 Crossref =
          MetadataResolver（引用核验权威，裁判与选手分离，避免自证循环），
          不做 discovery 选手；该节点从未实现，图示删除。】
   │
   ▼ 融合（SourceIdentity 去重 + 倒数排名融合）
CandidateSource（sources/candidates.json；pending_review → accepted/rejected）
   │ 用户/Researcher 确认（HITL 语义）
   ▼
LiteratureLibraryService（M6.2）── SourceStore（sources/，origin=AGENT_RETRIEVED/USER_ADDED）
   │                                     │
   │ MetadataResolver：Crossref/OpenAlex/S2/arXiv（既有 ScholarlyResolver.lookup 语义）
   │
   ▼ FullTextResolver（接口；M7.2 已落地：backend/src/search/fullText.ts）
   ├─ UnpaywallResolver（DOI → best_oa_location.url_for_pdf）
   ├─ ArxivPdfResolver（确定性 arxiv.org/pdf/<id>）
   └─ OpenAlexOaResolver（name "oa-url"：works API best_oa_location.pdf_url）
   └─ 用户上传 PDF（既有 HTTP 上传）
   │ 下载/入库 → 解析 → chunk 管线（复用 sectionChunking 模式 + contentHash）
   ▼
SourceChunk（sources/chunks/<sourceId>.jsonl）
   │
   ▼ RetrievalService ── RetrievalIndex（进程内 lexical [+ dense 可选]；Derived）
   │                     EmbeddingProvider（可选抽象）
   ▼ Context Budget Packing → Agent（Researcher/Writer/Reviewer/Citation）
   │
   ▼ EvidenceCandidate（quote 逐字校验）→ Verification → EvidenceStore
   │
   ▼ Writer / Reviewer / Quality Gate（既有闭环不变）
```

**进程位置**：虚线上除 SearXNG（外部 Docker 容器）与各上游 SaaS API 外，
全部组件在 PaperTeam backend 进程内（Node/TS）。**Optional 组件**：SearXNG
（无则 Web Search unavailable）、AMiner（无 key 则不注册）、Dense 检索（无
EmbeddingProvider 则 lexical-only）。

## 4. Provider strategy

| Provider | 层 | 角色 | 依据（分析报告） |
|---|---|---|---|
| SearXNG | WebSearch | 唯一 Web 底座（独立服务） | §3：唯一具备多引擎聚合/归一/去重/失败隔离/JSON API 的现成底座 |
| OpenAlex | AcademicSearch + Metadata + FullText(oa_url) | **primary** | §8.3：免费额度最大 + 摘要可重建 + cites: filter |
| Semantic Scholar | AcademicSearch + Metadata | enrichment + fallback | §7.1：429/503 高发 + 1rps → 不做 default；引用数/TLDR 有独有价值 |
| arXiv | AcademicSearch + FullText | preprint + PDF | 既有 connector + OA 全文 |
| Crossref | MetadataResolver | 引用核验权威（DOI 注册库） | §5.4：检索排序弱，保持核验定位 |
| AMiner | AcademicSearch | **China secondary + enrichment** | §6.3：境内托管+中文一等，但无前向引用/无精确引用数/免费无摘要/计费悬崖 |
| Unpaywall | FullTextResolver | DOI → OA PDF | §5.3：纯解析服务无检索能力 |
| （未来）Wanfang/NSTL/CNKI | AcademicSearch | 后续中国源扩展点 | 接口已预留（provider 注册制） |

策略要点：**Discovery 聚合在任何单源 unavailable 时继续返回其余源结果**
（借 SearXNG 聚合纪律）；**error ≠ not_found ≠ 空集**（D-0023 纪律在 search
侧延续）；AMiner 付费端点（searchPro 等）默认关闭，接入前必须先小额实测计费
（仓内 ¥0.30/¥0.70 双价格矛盾未决，§6.1）。

## 5. Data flow（Evidence 边界，逐步责任表）

| 步骤 | 谁创建 | 持久化 | authoritative | verification |
|---|---|---|---|---|
| SearchResult | SearchService | 否（进程内） | 否 | 无 |
| CandidateSource | ResearchDiscoveryService | 是（sources/candidates.json） | 候选清单是事实 | 无——候选≠可信 |
| SourceDocument | LiteratureLibraryService（SourceStore.add） | 是（sources/） | 是 | 文献级状态（解析/元数据），非内容可信 |
| SourceChunk | chunker（确定性，无 LLM） | 是（sources/chunks/） | 是（derived 但落盘） | 无 |
| RetrievedChunk | RetrievalService | 否（可确定性复现） | 否 | 无 |
| EvidenceCandidate | Researcher（Agent）→ EvidenceStore.append | 是（evidence.jsonl） | 是 | **unverified**（入库即此状态，既有行为） |
| Verification | 核验管道（确定性通道 + LLM judge 只见真实证据） | 更新 EvidenceStore | — | unverified → verified/plausible/mismatch/unverifiable |
| EvidenceStore 消费 | Writer/Reviewer/Quality Gate（既有） | — | 是 | supportStrength 进 Gate |

红线：snippet → 最多 plausible（level=metadata/abstract）；quote 校验失败
的 EvidenceCandidate 不得升级 verified；`verificationLevel=fulltext` 只能由
「quote 逐字匹配 chunk」或既有全文核验通道授予。

## 6. Failure model（Provider Health，冻结）

四态：`healthy / degraded / rate_limited / unavailable`（定义与转换见分析报告
§10.3）。要点：

- 状态由 **ProviderHttpClient 统一维护**（非各 provider 自写）；观测输入：
  调用结果、HTTP 状态（429/5xx）、Retry-After、AMiner HTTP-200 信封 code、
  SearXNG `unresponsive_engines`。
- `rate_limited`：冷却 = Retry-After（有界，硬帽如 60s）否则指数退避；冷却期
  不派发新请求，冷却结束自动恢复（不需要探测）。
- `unavailable`：连续失败 ≥3 次开路（熔断），半开探测恢复；Discovery 聚合
  自动绕开该源。
- `degraded`：部分失败/超时率高/SearXNG unresponsive_engines 非空——继续用，
  结果带 degraded 标记（供 prompt/前端如实呈现）。
- 全源 unavailable：Web Search → 结构化可重试错误；Academic Discovery → 若
  AMiner（境内）可用则兜底，否则 UNRESOLVED 风格错误——**不伪造空结果**。
- 超越样本（s2-mcp 教训，分析报告 §7.2）：退避 sleep 不持锁（消 head-of-line）、
  500 纳入统一 5xx 重试集、每请求总 deadline、每 provider 独立并发原语。

## 7. China availability strategy

- **Web**：自部署 SearXNG（Docker），engine 白名单 = cn.bing + baidu（+可选
  360/sogou 微信渠道），境外引擎（DDG/Brave/Startpage）在有代理时经
  `outgoing.proxies` 启用；SearXNG 自身的引擎挂起（CAPTCHA 1h / 429 180s /
  Cloudflare 15d）天然提供上游熔断，PaperTeam 侧只聚合 `unresponsive_engines`
  做 health 观测。
- **Academic**：OpenAlex/Crossref/S2/arXiv 直连（时通时断 → UNRESOLVED 语义 +
  重试 + 熔断）；AMiner 全境内托管做 secondary——任何境外源批量不可用时，
  中文/国内文献检索与元数据补全（paper_info 批量免费）仍可用。
- **配置面**：所有 provider 可独立 enable/disable（env），API key 缺失 = 该
  provider 不注册（系统照常启动，如实上报 not_configured——沿用 Runtime
  「健康≠就绪」语义，ARCHITECTURE §6.0.2）。
- **绝不**：以「翻墙可用」为前提设计任何 mandatory 路径；以 Google 系任何
  服务为 default/fallback 最后单点。

## 8. Licensing consideration（工程事实，非法律结论）

- **SearXNG（AGPL-3.0）**：独立进程 + 未修改源码 + 文档化 HTTP API 交互 =
  最小接触面（分析报告 §3.8 工程事实 A/B）；复制其代码进 PaperTeam =
  传染面（工程事实 C）——**禁止且本轮未发生**。PaperTeam compose 引用官方
  镜像而非 vendoring 源码；自维护的只有 settings.yml 配置文件（配置非程序
  作品的工程判断，如实记录：settings 覆盖是官方支持的部署方式）。
- **MIT 五项**（agent-search / paper-search-mcp / aminer-skill / s2-mcp /
  openalex-mcp）：借设计零复制，无义务产生；若未来引用具体实现片段，保留
  归属注释即可。
- **上游 SaaS 条款**：AMiner 计费接口的用量边界（成本护栏）进 ProviderHttpClient
  的 per-provider 配置；Unpaywall/OpenAlex 的 mailto 礼貌池标识复用既有
  CITATION_CONTACT_EMAIL 配置。

## 9. Rejected alternatives（明确拒绝及理由）

| 方案 | 拒绝理由（证据） |
|---|---|
| 直接依赖 agent-search（A） | Python 巨石 + SearXNG 常驻 + 上游无 API 承诺（1 squash commit）；PaperTeam TS 栈无法进程内依赖（分析报告 §4.9） |
| agent-search 作为旁路 HTTP 服务（B） | 多运维一个无鉴权 Python 服务；其 RAG 无 chunk 结构/引用靠 prompt——恰是 PaperTeam 最不能外包的部分（§4.5） |
| 引入 paper-search-mcp / s2-mcp / openalex-mcp 任一作为运行时 MCP server | ①PaperTeam 内部已有 Agent Runtime + customTools，内部 MCP 化是纯开销；②单源单用途（无聚合价值）；③paper-search-mcp 无 provider 抽象（§5.2）；④多一个 Python/Node 服务进程 |
| 把 SearXNG 嵌入 backend（subprocess 或源码内嵌） | AGPL 传染面（§3.8-C）+ Python 异构 + 破坏「backend 进程内完成一切」的部署简单性（D-0020 遗产） |
| 万能统一 SearchProvider（Web+Academic 一把抓） | 归一化/去重/健康语义互相污染；paper-search-mcp 的 4 套字段并存是实证（§5.2）；Web 结果（URL/snippet）与学术结果（DOI/venue）是不同数据形状 |
| Vector DB / Elasticsearch / Redis / Qdrant / Milvus | single-user + 每项目几十篇 × 数千 chunk，进程内索引毫秒级；被分析的 6 个项目也没有一个用外部向量库；违反 D-0013 文件优先与「不提前引入数据库」（分析报告 Q14） |
| 第一版 reranker（cross-encoder） | 语料小、上下文预算有限时收益存疑且引入新模型依赖；hybrid RRF + metadata filter 先行，真实命中率不足再评估 |
| 爬虫型兜底（agent-search WebFallback / FlareSolverr 反 CAPTCHA） | 脆弱 + 重 + 维护成本高（§4.8）；SearXNG 多引擎冗余已承担换源职责 |
| 内部 MCP 化（因分析对象用 MCP 就全 MCP 化） | 与 D-0008/D-0020 分层冲突；Pi customTools 是零开销内部通道（分析报告 Q15） |
| Google/Google Scholar 作为依赖 | 原则 2（大陆主流程无 Google）；SearXNG engine 与学术链路均不含 Google |
| 现状式「查证形 search()」继续当检索用 | 关键词被当标题做相似度门控（0.8/0.92），非标题形查询返回空（§2.2-1）——M6.3 必须实现真检索语义 |

## 10. Consequences

正向：M6.2-M6.5 有明确的接口契约与最小集；Evidence 闭环与既有 Quality Gate/
Citation Integrity 无缝衔接；大陆可用性有兜底路径；零新运行时重型依赖；
AGPL 风险被进程边界隔离。

代价与如实边界：
- SearXNG 是自部署组件（Docker），Windows dev 无 Docker 时 Web Search 不可用
  （optional 降级，文档提供指引）——接受。
- SearXNG 抓取型引擎（bing/baidu）天然随上游改版/风控漂移，属于上游风险，
  PaperTeam 侧以 health 模型 + engine 白名单缓解，无法根除——如实记录。
- 学术检索质量上限 = 开放 API 的元数据质量（无订阅源）；付费源（CNKI 等）
  不在 M6 范围——后续 provider 扩展点已留。
- AMiner 免费层无摘要——enrichment 链路设计为「免费可跑、付费可选」，不为
  付费端点引入 mandatory 路径。
- lexical-only 第一版的检索质量依赖 chunk 化质量与查询改写（Researcher
  负责 query 生成）；dense 层预留但默认关闭。

## 11. Implementation order（M6.2 → M6.5 实施入口）

> 顺序原则：先持久层（文献库）再检索层（discovery）再检索索引（RAG）再
> Evidence 管道——每步独立可验收，前置是后置的依赖。

**M6.2 Project Literature Library（下一步）**
- 入口模块：`sources/SourceStore.ts`（扩展：candidates 清单 / DOI·arXiv·URL
  导入路径 / AGENT_RETRIEVED 写入方 / 元数据补全）、`httpServer.ts`
  （sources 子资源路由扩展）、`workflow/definitions.ts`（不动——M6.2 不加
  stage）。复用：ScholarlyResolver.lookup 做 DOI/arXiv 导入的元数据解析。
- 交付：候选文献清单（accept/reject）、五种入库路径（PDF 上传已有 + DOI /
  arXiv ID / URL / 检索结果转正）、SourceIdentity 落库。

**M6.3 Academic & Web Search Service**
- 入口模块：新建 `search/` 域（`ProviderHttpClient`、`AcademicSearchService`
  + 各 provider 的真 search 实现、`WebSearchService` + `SearXNGProvider`、
  融合去重）、`skills/scholarlyTools.ts` 升级（search_papers v2 真检索 +
  web_search 工具）、`config/config.ts`（PAPERTEAM_SEARCH_* 配置节）。
- SearXNG：compose 增加可选 service + settings 模板（json format 开、limiter
  关、engine 白名单）；`PAPERTEAM_SEARXNG_URL` + readiness 探测。
- 交付：ResearchDiscoveryService 编排 + CandidateSource 产出 + Provider
  Health 观测（并入 /api/runtime/status 风格的诊断端点）。

**M6.4 Retrieval / RAG（本轮设计的 §12 架构落地）**
- 入口模块：sources chunk 管线（迁移 sectionChunking 模式 + per-chunk
  contentHash）、`RetrievalIndex`（进程内 lexical；dense+EmbeddingProvider
  可选）、`retrieve_library` customTool、Context Budget Packing。
- 交付：项目内检索进 Writer/Reviewer 上下文供给链路。

**M6.5 Evidence Pipeline & Workflow 接线**
- 入口模块：核验管道（quote 逐字校验 + 元数据通道复用 + judge 只见真实证据）、
  `workflow/definitions.ts`（research 阶段接入 discovery/检索结果的 stage
  化，research.idea 扩展或新增 stage）、ResearcherService prompt 升级
  （检索结果进 ResearchReport 结构、结果落 SourceStore）。
- 交付：Search→Candidate→Library→Evidence 全链路自动化 + 质量门禁联动。

## 12. TypeScript 接口草案（本轮只冻结形状，不实现）

> 原则：接口尽量小；方法数量按「第一版真实调用方」裁剪（openalex-mcp
> 「薄原语」教训）；全部放 backend/src/search/（M6.3 起）。

    | { kind: "error"; note: string }

  pageStart: number; pageEnd: number;
  text: string;
  contentHash: string;

## 13. 与既有决策的关系

- D-0013（三层状态）：chunk 文件是落盘 derived；索引=可丢弃 derived。
- D-0023（NOT_FOUND≠捏造≠检索失败）：search 侧延续（error≠not_found≠空集）。
- D-0008/D-0009/D-0026：检索服务是确定性代码 + Agent 消费，不新增 Agent 角色。
- D-0020：不为单一工具恢复外部 Gateway——SearXNG 是数据服务不是 Agent Runtime。
- D-0021（pymupdf 子进程 + AGPL 双许可先例）：SearXNG 的「独立进程 + 无修改 +
  接口交互」处理方式与之一致的工程取向，边界纪律写入本 ADR §8。
